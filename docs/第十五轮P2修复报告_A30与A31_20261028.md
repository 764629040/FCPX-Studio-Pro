## 1. A-30：bbox 越界防护

### 1.1 审核判断的前半段成立

> A-30 是合成路径缺少 bbox 越界防护，真实畸形 PSD 仍会产出乱码预览，
> 因为 `psd_parser.py` 指纹未变更、`thumbnail.py` 没有防护，**只换了样本，根因未修**。

**成立。** Round 14 我只新建了干净夹具，没在代码层加任何防护。

### 1.2 修复

`core/thumbnail.py` 新增两个函数：

```python
def crop_composite_to_canvas(img, canvas_w, canvas_h):
    """合成图尺寸与画布不一致时裁剪回收，返回 (image, adjusted)"""

def has_out_of_bounds_layers(psd_obj) -> bool:
    """检测是否存在 bbox 越界图层（诊断用）"""
```

在 PSD 合成路径接入：越界时裁剪并写旁路告警 `_thumbnail_warning.txt`。

### 1.3 但我必须指出一个事实：crop 在这个场景下不触发

实测 `vertical_wedding_9_16.psd` 的 `composite()` 返回尺寸**已经是 1080×1920**，
与画布一致，因此 `crop_composite_to_canvas` 走 passthrough 分支，**不做任何裁剪**。

也就是说：

| 手段 | 能否消除彩条 |
|---|---|
| `crop_composite_to_canvas` | **不能**。尺寸本就匹配，不触发；即便触发也只能裁掉越界区域，归不回正确像素 |
| `has_out_of_bounds_layers` | 能**发现**问题（真实价值所在） |
| 替换背景层（A-31 已做） | **能**。彩条源自 PSD 内部通道错位，必须换数据 |

**A-30 的真实价值是「检测能力」而非「修复能力」**——让畸形 PSD 不再静默流出。
若要真正修复彩条，需要重建图层（即 A-31 路径）。

这一点已在测试 `test_30_detector_is_the_real_value` 中如实标注。

## 2. A-31：横向零覆盖（已修复）

### 2.1 审核指出的证据缺口（完全成立）

Round 14 的 `vertical_9x16_true.psd` 是**像素层占位**：

| 检查项 | 实测 |
|---|---|
| 8 块中心 x | **全部 540.0** |
| 横向跨度 | **0.00%** |
| 纵向跨度 | 1277（66.51%） |

**而 A-24 出错的维度正是横向**（1080 竖版被塞进 1920 横版 comp，文字被横向拉伸）。
横向跨度为 0 时，comp 宽度再次写错也照样通过——这是结构性证据缺口。

**您说得对：换夹具的理由是横向分布，不是文字内容。** 我上轮把理由归到文字内容上是错的。

### 2.2 修复：采纳「基于旧夹具重建背景层」方案

新增 `tests/make_vertical_rebased_fixture.py`：
- 定位越界背景层 → `delete_layer()`
- `create_pixel_layer()` 新建 1080×1920 纯色背景
- **8 个真实 type 层完整保留**（含真实文本、字体、横向分布）

产物 `tests/data/vertical_9x16_rebased.psd`。

### 2.3 三夹具对比（决定性数据）

| 夹具 | 越界 | type 层 | **横向跨度** | 纵向跨度 | 缩略图彩条（红/绿） |
|---|---|---|---|---|---|
| 旧夹具 | **True** | 8 | **478.0 (44.26%)** | 108.5 | **119 / 48** |
| Round14 占位 | False | 8（像素） | **0.0 (0.00%)** ← 缺口 | 1277 | 0 / 0 |
| **Round15 重建** | **False** | **8（真实 type）** | **478.0 (44.26%)** | 108.5 | **0 / 0** |

**Round15 重建同时具备：真实横向分布 + 无彩条 + 真实 type 层。**

证据：`docs/round15_evidence/a30_a31_verify.json`

### 2.4 新增横向断言（按您指定规格）
