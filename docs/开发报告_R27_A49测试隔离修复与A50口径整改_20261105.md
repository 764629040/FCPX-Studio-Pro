## 一、A-49：`no_appkit` fixture 模块身份分裂修复

### 1.1 缺陷复述（复核方已实证，我方认可）

旧 fixture 位于 `tests/test_font_diagnosis_honesty.py`：

```python
monkeypatch.setattr(builtins, "__import__", fake_import)
for mod in [... "core.psd_parser" / "AppKit*" ...]:
    monkeypatch.delitem(sys.modules, mod, raising=False)
import core.psd_parser as fresh
importlib.reload(fresh)          # ← 模块身份分裂的源头
yield fresh
# teardown 又一次 pop + import + reload
```

跑序实证（复核方做，我方本轮修复后复核）：`font_diagnosis` 先跑 → `c_11` 后跑必挂；反序则过。全量 `pytest tests/` 默认字母序恰好是「font_diagnosis 在前」，所以全量必现 1 failed——不是跑序侥幸能躲掉的。

### 1.2 修复方式（与复核方建议的差异说明，先讲清楚再给代码）

复核方建议「用 monkeypatch.setattr 直接 patch 模块内的 AppKit 引用或 HAS_APPKIT 标志」。**我方核查事实：`core/psd_parser.py` 模块级既没有 `HAS_APPKIT` 标志，也没有模块级 AppKit 引用**——AppKit 全部是函数内延迟 import（`appkit_available()` L112、`check_font_availability_status()` L143、`check_glyph_coverage()` L200），所以「patch 模块内 AppKit 引用」这个落点在本代码库不存在。

等价且覆盖面更完整的 identity-safe 做法：**只保留 `monkeypatch.setattr(builtins, "__import__", fake_import)`，删掉全部 `sys.modules` 删除与 `importlib.reload`**：

- `import AppKit` 语句在**调用期**才走 `__import__`，被 fake 拦下即等效真实 Linux 无 AppKit（连 `sys.modules` 里已缓存的 AppKit 也一并生效，因为 fake 在查缓存之前就 raise）；
- 三个延迟 import 调用点（availability / status / glyph coverage）**全部**被覆盖，比单 patch 某个函数更接近真实环境语义；
- `monkeypatch` 在用例结束自动还原 `__import__`，**零手工清理、零 `del sys.modules`、零 reload**，模块对象自始至终唯一——这正是 A-49 要消除的污染路径。

复核方要求的两条硬性验收（不 del 后不还原 / monkeypatch.setattr 方式）均满足。

### 1.3 修复后的 fixture（`tests/test_font_diagnosis_honesty.py` L34–62）

```python
@pytest.fixture()
def no_appkit(monkeypatch):
    """A-49 修复：模拟无 AppKit 环境，但不碰 sys.modules、不做模块重载。……"""
    real_import = builtins.__import__

    def fake_import(name, *args, **kwargs):
        if name == "AppKit" or name.startswith("AppKit."):
            raise ImportError("simulated environment without AppKit")
        return real_import(name, *args, **kwargs)

    monkeypatch.setattr(builtins, "__import__", fake_import)
    import core.psd_parser as parser_mod  # 已导入的同一模块对象，不重载
    yield parser_mod
    # 无需任何手工恢复：monkeypatch 自动撤销 __import__ 补丁
```

### 1.4 同款缺陷顺带修复（`tests/test_round3_a9_a10_a13.py`）

排查发现 `test_round3_a9_a10_a13.py` 的 `test_no_appkit_parsing_yields_unverifiable_not_font_missing`（L83）与 `test_no_appkit_warning_text_is_not_misleading`（L124）是**同一套 delitem + reload + finally 手工 pop 还原**的写法。它没被复核方点名的唯一原因：该文件在默认字母序里排在 `test_r25_c_11` **之后**（`test_round3` > `test_r25`），跑序侥幸没踩到——和 R26 被点名的「跑序侥幸」是同一个性质。同缺陷一并修：删掉 delitem/reload/try-finally，只留 `monkeypatch.setattr` 拦 `__import__`。
