## 3. A-30 深挖：你的根因说法与实测不符

### 3.1 你说「彩条源自 PSD 内部像素数据本身」

我逐层单独 `composite()` 检查了旧夹具的每一层：

| 层 | 类型 | 尺寸 | bbox | 该层彩条 |
|---|---|---|---|---|
| 图层 0（背景） | pixel | 1920 × 1080 | (0,0,1920,1080) | **0 / 0** |
| 领衔呈现 | type | 38 × 175 | (308,388,346,563) | 0 / 0 |
| lead the presentation | type | 36 × 160 | (357,389,393,549) | 0 / 0 |
| 新娘 朱永宏 | type | 37 × 266 | (481,389,518,655) | 0 / 0 |
| THE BRIDE | type | 14 × 115 | (532,389,546,504) | 0 / 0 |
| 新郎 陈晗 | type | 37 × 220 | (653,389,690,609) | 0 / 0 |
| THE GROOM | type | 15 × 130 | (703,389,718,519) | 0 / 0 |
| 镇雄 | type | 37 × 82 | (747,388,784,470) | 0 / 0 |
| CITY | type | 14 × 49 | (798,389,812,438) | 0 / 0 |

**没有任何一层自身含彩条像素——连那个 1920×1080 的越界背景层，单独合成也是 0/0。**

### 3.2 那彩条从哪来

| 观察 | 数值 |
|---|---|
| 整幅 `psd.composite()` 彩条 | **42329 像素（2.04%）** |
| 彩条分布 bbox | **x[0..1079] y[221..1638]** |
| 背景层 bbox | (0, 0, 1920, 1080) |
| 彩条是否全在 y<1080 内 | **否**（最远到 y=1638，超出背景层 558 px） |
| 彩条是否全在 x<1080 内 | 是 |

**已证事实**（三条，均为实测）：

1. 逐层单独 `composite()`：**无任何一层含彩条像素**（含越界背景层，0/0）；
2. 整幅 `psd.composite()`：**42329 个彩条像素，且越出背景层范围**（y 最远 1638 > 1080）；
3. 逐层贴图到画布：**彩条 0/0**。

**由以上三条可判定：彩条不是任何一层的像素数据，而是整幅合成过程产生的伪影。**

**推断（非已证）**：`psd.composite()` 在处理 1920 宽层写入 1080 宽画布时，疑似发生缓冲区跨行错位（row stride 不匹配）；逐层贴图时每层在自己 bbox 内合成、再裁到画布内，错位前提不成立，故彩条归零。**审核方未深入 psd-tools 源码确认该机制**，此处仅作解释性推断，不影响「逐层贴图可消除彩条」这一实测结论。

> 这一条很重要：**根因不是「数据坏了」，是「合成器用错了」。** 数据坏 → 只能换数据（你的原判）；合成器用错 → 换合成方式即可（实测可行）。

### 3.3 「裁剪不触发」——这点你说得对

`crop_composite_to_canvas` 只在 `img.size != canvas` 时生效。实测 `composite()` 返回尺寸**恰好等于** 1080×1920，所以 crop 永远走 `return img, False`，**确实不触发**。你这句判断准确，没有虚报。问题不在你判断错了，而在**你只做了方案一，就把「方案二做不到」当成了结论**。

### 3.4 一处事实偏差（须互相核对）

| 来源 | 全分辨率彩条 | 缩略图彩条 |
|---|---|---|
| 你的测试文档 | 84 红 / 40 绿 | 6 红 / 3 绿 |
| 审核方实测（psd-tools **1.26.0**） | **28852 / 13477** | **119 / 48** |

差 20–340 倍。`test_30_legacy_fixture_color_noise_is_intrinsic` 只断言 `red > 0 or green > 0`，所以**两个数值都能通过**，不构成假通过。但这种量级差异说明两侧 `psd-tools` 版本或解码路径不同。**建议你在报告里标注所用版本**，否则「彩条很轻微、只有 6 个像素」会让人误判严重程度——实际是 2.04% 的画面被污染。

## 5. A-30 最终裁定

### 5.1 判：**保留为活缺陷（P2），不关闭**

| 口径 | 裁定 |
|---|---|
| A：不再静默流出 | **半达成**。`has_out_of_bounds_layers` 能检出（旧夹具 True、新夹具 False，实测正确），`_thumbnail_warning.txt` 能落旁路。但**用户看到的图仍是坏的**，只是旁边多了个 txt |
| B：消除彩条 | **可达成，且已跑通**。逐层贴图实测 0/0 彩条、0 像素回归 |
| **应采用的口径 C** | **「合成改用逐层贴图，彩条不再产生」** —— 既消除彩条，又不依赖告警兜底 |

### 5.2 必须同时完成的两件事

1. **`generate_thumbnails_from_psd` 的合成改用逐层贴图**（保留 crop 作为尺寸兜底，保留检测器作诊断）；
2. **背景层边缘延伸填充**。

第 2 点是我原型暴露的瑕疵，**必须如实告诉你**：逐层贴图后，旧夹具背景层只有 1920×1080，裁到 1080×1920 画布后只覆盖上半部，导致**下半部 13.1% 非透明、86.9% 空白**。彩条是没了，但画面变成「上半有图、下半全黑」。

这不是逐层贴图方案的错，是**背景层本身尺寸不足**——真实畸形 PSD 也会这样。所以需要：当背景层 bbox 小于画布时，**取其边缘像素向外延伸填充**（或按画布尺寸纯色填充），保证整幅无空洞。

### 5.3 验收标准（可执行）

| 项 | 标准 |
|---|---|
| 旧夹具缩略图彩条 | 全像素 红 == 0 且 绿 == 0 |
| 旧夹具缩略图非透明率 | **≥ 99%**（不得出现下半空白） |
| 新夹具（rebased）像素回归 | 与 `composite()` 逐像素差异 **== 0** |
| 新夹具缩略图 | 彩条 0/0，尺寸 360×640 / 108×192 |
