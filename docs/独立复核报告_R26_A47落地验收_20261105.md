## 六、新发现缺陷（2 项 P2）

### A-49（P2）测试隔离缺陷：`test_font_diagnosis_honesty.py` 污染后续用例

**现象**：全量跑 `pytest tests/` 必现 `1 failed`：
```
tests/test_r25_c_11_media_integrity.py:54: AssertionError: 媒体失败必须有诊断条目，不得静默
```
但 `c_11` **单独跑必绿**。

**根因（我定位到 fixture 级）**：`tests/test_font_diagnosis_honesty.py` 的 `no_appkit` fixture 会 `del sys.modules["core.psd_parser"]` 并 reload，造成**模块身份分裂**：
- 后续用例 `monkeypatch` 打在「重载后的新模块对象」上；
- 而 `c_11` 调用的是收集期绑定的「旧模块」函数，其 `__globals__` 是另一份 dict；
- → 补丁失效 → 渲染**真的成功** → `media_error` 为空 → 「媒体失败必须有诊断条目」断言失败。

**顺序依赖实证（我做的对调实验）**：

| 顺序 | 结果 |
| --- | --- |
| `c_11` 先 → `font_diagnosis` 后 | **8 passed** |
| `font_diagnosis` 先 → `c_11` 后 | **failed**（复现全量同一失败） |

**为什么开发方没发现**：他们日志里 `test_font_diagnosis_honesty` 排在**第 23 位（最后）**，在 `test_r25_c_11`（第 14 位）**之后**，恰好避开了污染。这是典型的「跑序侥幸」，不是修复。

**性质**：产品代码本身没问题（c_11 单跑绿、媒体失败确实大声报），是**测试工程质量缺陷**，会让 CI 随机红/绿，掩盖真回归。必改。
