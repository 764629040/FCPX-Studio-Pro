- 检索「全仓无磁盘空间检查」：路径一 `grep -rn "disk_usage" core/` → 0 命中；路径二 读 `build_template_atomic` 全文（第 493–670 行）确认 pre-flight 仅有存储就绪与权限两项，无空间检查 → 确认缺口成立。

1. **T3 GUI 接入未做**：指令允许「无 GUI 也要先有 core 能力和测试，GUI 可后补」。本轮仅交付 `core/template_versions.py` 能力与 4 条测试，右键「历史版本」列表 UI 未实现。
2. **T4 GUI 接入未做**：`BatchRunner` core 能力已就绪，但 `gui/main_window.py` 的批量导出入口（`_on_batch_export_all`）未改造为接入 BatchRunner——该入口仍走旧的逐文件循环。断点续跑 UI 未实现。
3. **T2 `on_conflict="ask"` 未在真实 GUI 事件循环中验证**：回调逻辑已单测覆盖，但 QMessageBox 确认框的实际交互未在真机 UI 中点击验证（自动化测试不弹真实框）。
4. **T1 `shutil.disk_usage` 异常路径仅覆盖 `free < required`**：`disk_usage` 抛 `OSError` 时按 `free=0` 处理会抛 StorageSpaceError，但该路径未单独单测（真实环境 disk_usage 极少抛 OSError）。
5. **未声称真机 UI 可用**：观感与最终签字权在用户。
6. 128 卷未写入任何内容。
7. `no_appkit` 模拟环境的 18 个 `ERROR at setup`（AppKit 依赖的 setup 失败）与本轮无关，本轮未单独复跑 no_appkit。
