## 二、A-51（P2 新缺陷）GUI 高亮未接入实际交付界面

### 2.1 现象

用户无法做 A-47② 的视觉验证，因为**外部可双击启动的程序不含该功能**。

### 2.2 证据链（时间戳 + 代码双侧证明）

| 项 | 证据 |
| --- | --- |
| 可双击程序 | `FCPX Studio Pro.app/Contents/MacOS/FCPXStudio`，Mach-O arm64，**392 472 B，构建于 10-26 14:58** |
| 该程序本质 | Swift 原生（源码 `FCPXStudioNative/Sources/FCPXStudio/`），启动后调 `core/cli_bridge.py` 走 JSON socket 桥 |
| `.app` 是否含 PyQt | **否**，包内无任何 Qt 相关文件 |
| 高亮实现位置 | `gui/inspector_panel.py`（PyQt6 版），**修改于 11-04 15:12** |
| 高亮判定 | `core/missing_font.py::missing_glyph_layer_state`，**11-04 15:12** |
| Swift 侧字段 | `LayerModel.swift` **无** `marked_text` / `missing_glyph_visible_marker` / `highlight_missing_font` 任一字段 |
| Swift 名称列渲染 | `InspectorView.swift:350-354` 仅 `NSTextField(labelWithString: layer.name)` + 纯白 11pt，**无 ⚠ 徽标、无橙色前景、无 tooltip** |

→ **时间差 9 天 + 代码零接入**：A-47② 的逐层高亮写在 PyQt6 界面里，而项目对外交付的是一个 10 月 26 日构建的 Swift 原生程序，两者是两套 UI，且没有为 PyQt6 版提供 `.app`/`.command` 启动入口（唯一 `.command` 只是 `open "FCPX Studio Pro.app"`，打开的仍是 Swift 版）。

### 2.3 原生侧实际能看到什么（不是全无提示）

`InspectorView.swift:363-370` 有一条**整体诊断条** `diagnosticsBox`，数据来自 `cli_bridge` → `diagnostics.warnings`，而 `core/psd_parser.py:1007` 在缺字时确实会 append：

```
图层 '{name}' 存在缺字/缺字体风险 ({font_status})，已用可见缺字标记并高亮，未静默替换默认字体
```

所以你在原生界面**能看到一行橙色文字告警**，但看不到：逐层 ⚠ 徽标、橙色图层名、悬停缺字清单、预览列 □ 显示。这就是缺口。

### 2.4 影响评估

| 维度 | 影响 |
| --- | --- |
| 产品质量 | **无影响**。缺字已进 `.moti`（A-47① 已关闭，`□` 在 FCPX 里肉眼可见），诊断也进了 warnings 列表 |
| 可见性 | 降级为"一行文字告警"，而非"逐层高亮"。信息不丢，但发现效率下降 |

### 2.5 定性

与 A-50 同类模式：**做的那套 ≠ 交付的那套**。测试证明 PyQt6 版接线正确（7 passed），但用户实际拿到的程序是另一套。这说明验收口径里缺一条硬约束：「**凡 UI 类改动，必须指出用户从哪个入口能打开看到**」。

## 三、程序打开方式（回答"我不知道怎么打开"）

### 3.1 对的做法

1. 打开「访达」（Finder）；
2. 进到项目文件夹：`未命名文件夹/FCPX_Studio_Pro`；
3. 找到 **`FCPX Studio Pro`** 这个应用（蓝色/白色图标，带 .app 后缀但访达默认隐藏后缀）；
4. **双击它**。

### 3.2 如果双击没反应或提示"无法验证开发者"

不要双击，改成：**右键点它 → 选「打开」→ 弹窗里再点「打开」**。只需做一次，之后双击就能正常启动。

> 项目里那个 `启动FCPX_Studio.command` 是同一个东西的另一个入口（它内部只是打开上面那个 .app），你上次报过权限问题，可以不用它。

### 3.3 打开后你会看到

- 左侧：PSD 文件列表（可点「选择 PSD 目录」指向你的素材目录）
- 中间：无限画布，显示画幅和图层
- 右侧：检查器，**顶部有「📐 画幅规格」一行 + 下面一条彩色诊断文字**

**注意**：就目前这个版本，右侧图层列表里**不会有** ⚠ 徽标和橙色高亮（这就是 A-51）。你只能在顶部诊断条看到一行橙色告警文字。

### 3.4 建议

**这一步微验证先别做**。等你手上拿到接了高亮的新版本再验，否则看到的必然是"没有高亮"，容易误判成缺陷。等 R27 把高亮接进原生界面（或给你一个 PyQt6 版的启动入口）之后，我再给你精确的点验步骤。
