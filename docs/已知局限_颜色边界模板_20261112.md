# 已知局限 · 文字取色「未取到」（2026-11-12，v2 复核修订）

> v1 一稿把根因写成「层外 `<style>`」，并把 4 个模板按同构推断标成禁用；全库对账 + 真解析器实测后，
> 这两条都被推翻。本版以 `reports/verify_item5_color/核对报告.md` 为准，一稿的推断行不再保留。

## 一句话

面板对取不到填充色的文字层一律禁用（**宁可禁用不假色**）。全库 1033 个文字层里 141 层显示「未取到」：
其中 **39 层是真缺口**（`面/渐变` 链解析器不认），其余 **102 层是正当空态**（图片/纹理填充，或只有描边/阴影色）。
本轮只记档不修；是否补 `面/渐变` 路径另立问题单评审。

## 现象

- 在 FCPX 里：这些模板的文字填充色参数可改、改完生效。
- 在设计器面板：色块灰占位、HEX 框文案「未取到」、色块与 HEX 框禁用（不可点）；同一层的文本、字体、字号、对齐、X/Y 不随之禁用。
- 编辑态下「文字样式」分组被主动隐藏（`InspectorView+MotiEdit.swift:106`，为把保存按钮挤进首屏），「未取到」只在只读预览里可见。

## 根因（两条口径，不要混）

### A. 真缺口：`面/渐变` 链不在取色优先级内

`resolveTextColor`（`MotiDocumentParser.swift:486-528`）只认四条：

1. `Face/Color`
2. `面/颜色`
3. `表面/颜色`
4. 渐变首色标：`表面/渐变`、`Face/Gradient`、style 直挂 `渐变`

`面(14) / 渐变(17) / RGB / RGB1 / 颜色` 这条链**三条渐变兜底都不覆盖**，于是返回 `nil`。

实测实证（我独立解析 XML 复核）：

```
名称条 01  L3 id=1825779821  text="총 3문제 성공!"
  层内 面/渐变/RGB1/颜色 = #FFE700（红 1.0 / 绿 0.9045 / 蓝 0）
  产品解析器实测：color=(nil)  → 面板「未取到」
```

规模：**39 层 / 38 个文件 / 33 个内容不同的模板**（明细 `缺口清单_39层.tsv`，已独立复算 39/38/33）。

### B. 层外 `<style>` 不是元凶

全库只有 7 个文件存在挂在 `group > scenenode` 下、没有 `<layer>` 祖先的 `<style>`。但那些对象**根本不是 layer**，
不会进图层表，也就没有控件能被它禁用。口径「层外 style 带色且本层取不到色」只有 **3 个路径 / 2 个模板**，
且这 3 条的根因仍落在 A（`面/渐变`）或图片填充，**没有一条是由层外 style 直接造成的**。
把祖先链上的颜色拿来用 = 张冠李戴，会把图片填充的字显示成隔壁那段的颜色。

## 为什么本轮不修

- 补 `面/渐变` 属于**取色口径变更**：要先定它与 `表面/渐变` 的优先级、会不会与「轮廓/颜色不作主色」的既定口径冲突，必须走问题单评审，不能顺手加一条路径。
- 回归面覆盖全部 1243 个可解析模板；现行为真值缺失即禁用，不伪造颜色——假色比禁用更坏：面板看到一个色、FCPX 里是另一个，会直接导致成片配色错误。
- 不改写 `.moti`、不落盘；局限只停留在「读不到就不给改」。

## 影响面

- 只影响填充色的取值与该控件可用性；文本、字体、字号、对齐、位置 X/Y 不受牵连。
- 同一模板内挂在 `<layer>` 下的其它取色点（形状填充色等）仍可正常读取。
- 不涉及写回：`.moti` 全程只读，面板禁用不会产生任何写操作。
