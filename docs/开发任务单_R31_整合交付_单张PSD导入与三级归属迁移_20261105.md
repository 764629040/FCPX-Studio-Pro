## 二、A-61 拖放导入（P1）

### 根因

- `FCPXStudioNative/Sources/` 全部 10 个 Swift 文件（1780 行）中：`registerForDraggedTypes` **0 处**，`draggingEntered` / `draggingUpdated` / `performDragOperation` / `prepareDragOperation` / `NSDragging` **均 0 处**。
- `MainWindowController.swift:41-51` 用标准 `NSWindow` 创建，未做任何拖放注册。`NSWindow` 默认不接收文件拖放 → 系统层面就没有接收方，用户看到的就是"完全没反应"。
- **`gui/main_window.py:56` + `351-372` 其实早就写好了拖放**（单文件 + 文件夹递归 + 自动选中），但交付物走 Swift 原生壳，**这段代码是死代码**。

### 实现要求

1. 给 `window.contentView` 套一层自定义 `NSView` 子类（如 `DropAcceptingView`），`init` 中 `registerForDraggedTypes([.fileURL])`；实现 `draggingEntered(_:)`（校验 `.psd` 或含 psd 的目录后返回 `.copy`）与 `performDragOperation(_:)`（`sender.draggingPasteboard.readObjects(forClasses: [NSURL.self])`）。
2. **画布区 + 整个窗口都必须能接**（用户最可能往画布中间丢）。
3. 新增 `importPsdPaths(_ paths: [String])`，与现有 `loadPsdDirectory` 并列使用：
   - 单个 `.psd` → **追加**进 `psdFiles`（不是清空）、`reloadData()`、`selectRowIndexes` + `selectPsdFile(at:)` 自动渲染；
   - 目录 → 沿用现有递归扫描；
   - 混合多项 → 逐个分类处理，psd 全收。
4. **去重**：路径已在 `psdFiles` 中则不重复追加（对齐 PyQt 侧 `_append_psd_files`）。
5. 拖入非 psd 文件 → **不崩溃、不静默**，明确提示"仅支持 .psd 文件或包含 .psd 的文件夹"。
6. 视觉反馈：`draggingEntered` 后窗口有可见高亮（边框/遮罩）。加分项。

## 三、A-63 存储归属三级判定（P1）

### 根因（比表面现象更严重）

1. `core/symlink_manager.py:9`：`DEFAULT_SYSTEM_MOTION_DIR = os.path.expanduser("~/Movies/Motion Templates.localized")`，`system_root` **8 处引用全指向它**；`get_installed_plugins():129` 只 `listdir` 这一个目录。
   → **但 `~/Movies/Motion Templates.localized` 在 FCPX 语义里是「用户」级，不是系统级。** 代码把它叫 `system_root`、并当「系统盘」展示，是整个误导读者的源头。
2. `AssetHubView.swift:189`：`p.isSymlink ? "🟢 外置软链接 (0系统盘占用)" : "⚠️ 系统内置盘 (占用存储)"`
   → **用一个布尔值（是不是软链接）冒充"归属层级"**。非软链接只代表"没外链到外置盘"，跟"是不是装在 App 包里"毫无关系。
3. **App 内置级从未被扫描**：`FCPXStudioNative/Sources` 全量检索 `METemplates` / `Final Cut Pro.app` / `/Library/Application Support` → **均 0 处命中**。

### 三级根目录表

| FCPX 显示 | 底色 | 磁盘真实位置 |
|---|---|---|
| **内置** | 黄 | `<FCPX>.app/Contents/PlugIns/MediaProviders/MotionEffect.fxp/Contents/Resources/METemplates.localized/<分类>` |
| **用户** | 绿 | `~/Movies/Motion Templates.localized/<分类>` |
| **系统** | 紫 | `/Library/Application Support/Final Cut Pro/Templates/<分类>` |

> 用户只给了前两条，第三条从 FCPX 自身界面截图确认存在，按标准位置实现；真机先 `ls` 确认再启用，不存在则该级显示为空。

### 实现要求

1. 建 `enum TemplateTier { case builtin, user, system }`，**三级各自独立扫描、独立标注**。
2. **App 包动态定位，禁止写死 App 名**（用户机器上是 `Final Cut Pro Creator Studio.app`，不是标准名）：
   - 优先 `NSWorkspace.shared.urlForApplication(withBundleIdentifier: "com.apple.FinalCut")`；
   - 兜底：遍历 `/Applications` 下 `*.app` 且包内含 `Contents/PlugIns/MediaProviders/MotionEffect.fxp` 的候选；
   - 都找不到 → **优雅降级**：该级显示「未检测到 FCPX」，**不崩溃、不清空整表**。
3. **同一名称出现在多级时全部列出、各自标注**，不要悄悄去重（用户需要知道装了几份、哪份生效）。
4. **「存储位置」必须拆成两个维度，都要可见**：
   - 维度 A **归属层级**：内置 / 用户 / 系统
   - 维度 B **磁盘形态**：实体（占用系统盘 N MB）/ 软链接 → 外置盘（0 占用）
   - 建议拆两列（「归属」+「磁盘形态」），或复合文案 `用户 · 软链接(0占用)`。**绝不允许再用 B 冒充 A。**
5. **清除误导命名**：`system_root` → `userTierRoot` 之类；`DEFAULT_SYSTEM_MOTION_DIR` 改名或加注释说明它是**用户级**目录；全项目清理把 `~/Movies/...` 称作「系统盘」的文案。
   > `core/symlink_manager.py` **不在 110 项红线内，可以改**。`core/motion_builder.py` 仍然**不许碰**。
6. 支持按归属层级排序/筛选（内置/用户/系统三档）。

## 五、A-64 跨层级迁移 + 内置级只读/可写开关（P2）

### 5.1 迁移能力

1. 对**单条**选中项提供「移动到 …」：`内置 / 用户 / 系统`（当前所在级置灰）。
2. 迁移 = 先 `moveItem` 到目标级同名目录 → 成功后再删源。**失败必须回滚，绝不允许"两边都没有"或"两份都在"。**
3. 目标已有同名项 → **不覆盖**，弹冲突提示（覆盖 / 跳过 / 改名三选一）。
4. 大模板（单条可达 1.7 GB）迁移要有进度提示，**主线程不可阻塞**（沿用现有 `DispatchQueue.global` + 回主线程刷新的模式）。
5. 完成后自动 `refreshList()` 并定位到刚移动的那一项，给出明确结果提示。

### 5.2 内置级默认只读（**人工本轮明确决定**）

> 人工决定原文：*「内置级的不用管它就行了嘛，那你就只读就可以了嘛。当然，我们只读它是可以改的。这个软件的设置里可以修改，比如设置"内置集可写"和"只读"这两种模式。假如用户非要修改，把它安装到内置集里面去，那也没关系，给它加一个开关就好了。但是默认情况下，内置集的东西是只读的，不能修改那个 APP。」*

1. **默认 `builtinTierWritable = false`（只读）**：
   - 「内置」级条目的「操作」列迁移入口**禁用**，显示「🔒 只读」状态，悬停说明"内置级默认只读，可在设置中开启写入"；
   - 拖拽/键盘快捷键等其它可能触发写入内置级的路径**一并拦截**；
   - **扫描与展示不受影响**（只读只限制"写入 App 包"，不限制"看"）。
2. **设置入口**：当前原生壳**根本没有设置界面**（`main.swift` 仅注册「关于 / 退出 / 打开 PSD 目录 / 最小化 / 前置所有窗口」）。需新建：
   - 菜单「FCPX Studio Pro → 设置…」（**⌘,**）+ 素材库页顶栏加「⚙️」按钮，二者都打开同一设置面板；
   - 设置项：`内置级写入权限` → 单选 `只读（默认，推荐）` / `可写（高级，有风险）`；
   - 持久化到 `NSUserDefaults`，key 用 `builtinTierWritable`，**默认 false**；面板内实时生效，无需重启。
3. **开启「可写」时必须给强警告**（不是一句"有风险"，要写清后果）：
   > 「写入内置级会修改 FCPX 应用程序包内部文件，可能导致 **应用签名失效、Gatekeeper 拦截、FCPX 无法启动或内置模板全部不加载**。更安全的替代方案是迁移到『系统』级。是否继续？」
   - 提供「改回只读」的一键入口，并展示当前状态。
4. **迁移到内置级前**（仅在已开启可写时）：
   - 二次确认（同上文案）；
   - **自动备份源目录到 `~/Movies/FCPX_Studio_Backup/<时间戳>/`**，UI 提供「撤销上次迁移」；
   - 若因权限失败，**明确提示"需要管理员授权"**，不许静默 sudo、不许只弹一句"搬家失败"。
5. **主推路径是 `用户 ↔ 系统`**（两者都可正常写、不破坏签名）。`内置` 级默认作为**只读展示**存在。

### 对 A-54 断言调整的专项审查（这是本轮唯一有"作弊嫌疑"的动作，重点查了）

开发方把 `test_no_appkit_warning_text_is_not_misleading` 从「**逐条**告警必须含风险词」改为「**至少一条**含风险词」。审核方判定**不构成弱化**，理由三条：
