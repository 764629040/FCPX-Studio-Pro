## 二、A-49 测试隔离修复 —— 通过

### 2.1 修复方式核对（我读源码）

`tests/test_font_diagnosis_honesty.py` 的 fixture 已彻底重写：

```python
real_import = builtins.__import__
def fake_import(name, *args, **kwargs):
    if name == "AppKit" or name.startswith("AppKit."):
        raise ImportError("simulated environment without AppKit")
    return real_import(name, *args, **kwargs)
monkeypatch.setattr(builtins, "__import__", fake_import)
```

**三项关键核验**：

| 核验项 | 结果 |
| --- | --- |
| `del sys.modules` / `importlib.reload` / 手工 pop 是否清零 | ✅ 全目录扫描 0 命中 |
| 是否 identity-safe（模块身份全程唯一） | ✅ 不触碰 `sys.modules`，只拦 `__import__` |
| 是否覆盖原先三个调用点（availability / status / glyph coverage） | ✅ `psd_parser` 对 AppKit 全是**函数内延迟 import**，拦截导入即等效覆盖全部 |
| 是否 monkeypatch 自动还原 | ✅ 用 monkeypatch，无手工 try/finally |

**关于落点选择的说明（开发方的判断正确）**：报告里那句「`psd_parser` 模块级没有 HAS_APPKIT 标志、也没有模块级 AppKit 引用，全是函数内延迟 import，所以『patch 模块内 AppKit 引用』这个落点不存在」——我核了源码，**属实**。拦 `__import__` 是此处唯一可靠的等价做法。

### 2.2 同族缺陷清查结果（我全目录扫）
