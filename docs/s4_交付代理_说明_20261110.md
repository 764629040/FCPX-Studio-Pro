## 3. 两个 s4_* 脚本为何未执行

**硬阻塞未解除**：现场 `FCPX Studio Pro R2.app`（PID 96268）与 `Final Cut Pro`（PID 97387）**都在运行**。
用户要求 S4.1 / S4.3 均须「用户退出 R2.app 后」才可执行；覆盖运行中的 Mach-O 会让 App 崩溃。

因此本轮对这两个脚本**只做落盘 + `bash -n` 静态语法检查**，**从未调用**其 `--help`、`--dry-run` 或主体流程：
未装包、未重签、未重建 dmg、未退出/重启任何 App、未动 FCPX 库、未写任何 `.app` 包。

脚本自身也把 `pgrep` 检查做成**第一道硬闸门**：只要 R2.app 进程在，直接 `exit 5` 报错，不会往下走。

### 执行前集成方必须做的事

1. **先重编**：`/tmp/fcpx_wd/release/FCPXStudio`（3381096 B）是 **TR-013 产物**；S1 代理正在改 UI 源码修
   TR-012 / TR-014，集成阶段必须重编，否则 `s4_install_and_sign.sh` 会按 3381096 B 硬拒。
   ```
   cd FCPXStudioNative && swift build -c release --build-path /tmp/fcpx_wd --disable-sandbox
   ```
2. 用户**主动退出** R2.app（FCPX 不必退，但装包期间不要动它的库）。
3. `BUILD_BIN=<新产物> tools/s4_install_and_sign.sh --dry-run` → 看闸门与命令序列；确认无误去掉 `--dry-run`。
4. `tools/s4_rebuild_dmg.sh --version v1.1 --dry-run` → 确认后去掉 `--dry-run`；
   默认产物只留在 `/tmp/s4_dmg_out/`，**不往外置卷写大文件**。

### ⚠️ 集成重编前必须扫清的并发 WIP（S4 只读观察，未改任何文件）

现场 `FCPXStudioNative/Sources/FCPXStudio/Performance/` 有 4 个 S3 代理的 WIP 文件
（`S3GridLayout.swift` / `S3PerformanceFacade.swift` / `S3ThumbnailCache.swift` / `S3ViewportReuseEngine.swift`）。
S1 的 `reports/verify_tr012_tr014/TR-012_TR-014_验收报告.md` §1 明确记录：验证期间
`S3ThumbnailCache.swift` 有 `expected 'var' keyword in property declaration` 等 130 个编译错误且错误数在变化，
因此其直编**排除了 `Performance/`**，并且**没有跑集成阶段 `swift build -c release --build-path /tmp/fcpx_wd`**。

结论：集成方按上面第 1 步重编时，若 S3 的 WIP 仍未收敛，全量 `swift build` 可能直接失败。
本脚本不做源码改动、不替 S3 修编译错误、也不自动排除任何源码目录（排除源码属于集成方的构建决策）。
**重编必须先由集成方确认整棵 `Sources/` 能 0 error 编译**，否则 `s4_install_and_sign.sh` 拿不到可信的新产物，
装包与 dmg 重建都应继续停住。
