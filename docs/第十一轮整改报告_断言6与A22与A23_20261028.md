## 1. 断言 6：补充 view 层全局单例协调器

### 1.1 审核指出的缺陷

> 实测 4 个图元同时 hover 会展开 4 个，3 个图元同时 selected 会展开 3 个。
> 悬停受鼠标位置限制，但选择不受限，框选一片文字层就会同时展开多个徽章。
> **`test_06` 里写的是 `assert len(expanded) == 2`，把违规当成了预期。**

**两条批评都成立。** 尤其 `== 2` 那条——我把违反规格的行为写成了断言预期。

### 1.2 实现

图元侧：只表达「意愿」，不作最终决定。

```python
def _wants_expand(self) -> bool:
    """选中或悬停——仅表达意愿"""
    return bool(self.isSelected() or self._hovered or self._badge_expanded)

def _is_badge_expanded(self) -> bool:
    """最终决定权交给视图协调器"""
    view = self._owner_view()
    if view is not None and hasattr(view, "_expanded_item"):
        return view._expanded_item is self and self._wants_expand()
    return self._wants_expand()
```

视图侧：仲裁单例。

```python
self._expanded_item = None
self.scene.selectionChanged.connect(self._reconcile_badge_expansion)

def request_badge_expand(self, item):
    """抢占单例，旧持有者自动收回"""
    prev = self._expanded_item
    self._expanded_item = item
    if prev is not None and prev is not item:
        prev.update()
    item.update()

def _reconcile_badge_expansion(self):
    """选中集合变化后重新仲裁：悬停优先，否则取任意一个"""
```

## 2. A-22：色点屏幕像素补偿

### 2.1 问题

`DOT_SIZE = 4.0` 是**画布单位**，44% 缩放下屏幕仅 `4 × 0.44 = 1.76px`，肉眼几乎不可见。

### 2.2 实现

```python
DOT_MIN_SCREEN_PX = 4.0

def _dot_size_in_scene(self) -> float:
    """按视图缩放做屏幕像素补偿：任何缩放下至少 4px"""
    scale = self._current_view_scale()
    if scale <= 0:
        return self.DOT_SIZE
    min_units = self.DOT_MIN_SCREEN_PX / scale
    return max(self.DOT_SIZE, min_units)
```

命中区同步跟随补偿，保证点击目标始终大于视觉。

### 2.3 验证（各缩放级别）

| 缩放 | 画布单位 | 屏幕 px |
|---|---|---|
| 1.00 | 4.00 | **4.00** |
| 0.75 | 5.33 | **4.00** |
| 0.50 | 8.00 | **4.00** |
| **0.44** | **9.09** | **4.00**（修复前 1.76） |
| 0.25 | 16.00 | **4.00** |
| 0.10 | 40.00 | **4.00** |

### 2.4 断言 1 的分层修正

A-22 补偿会使色点实际尺寸 > 4，与原断言 1「色点 4×4」冲突。已分两层：

- **基准**：`DOT_SIZE == 4.0`（不变）
- **实际**：`local.width() >= 4.0` 且正方形、中心锚点

这样既保留断言 1 的原意，又容纳 A-22 的补偿语义。
