## 五、A-42 判定：加载路径闭合，参数编辑路径待确认

### 已闭合（有真机证据）

| 验收项 | 结果 | 证据 |
|---|---|---|
| ① Titles 里能看到 T01、T23 | ✅ | 截图图块 |
| ② 拖进时间线 | ✅ | 截图 00:08 / 00:09 两段片段 |
| ④ 不闪退、不报错、预览图正常 | ✅ | 缩略图正常 + 用户明言"可以正常使用" |

**这条很关键**：崩溃栈是

```
#13 -[FFMotionEffect _backgroundLoadDocument:onTask:]
#11 OZDocument::open(PCURL const&)
#7  OZScene::parseEnd(PCSerializerReadStream&)
#4  TXTextLayout::didFinishLoadingIntoScene()
#2  TXTextLayout::applyAllCaps(__CFString*)
```

**整条链路发生在"文档装载"阶段。** 用户能把模板拖进时间线并正常显示，等于**整条装载链路已跑通**，`applyAllCaps` 没有踩到空指针。

→ **A-42 的装载路径根因，真机确认闭合。**

### 待确认（尚未有真机证据）

| 验收项 | 状态 |
|---|---|
| ③ 改一处 `Text 01`、拖一次 `Position 01` | ⏳ **用户未执行/未告知** |

**为什么这一项还要做**：崩溃栈第 3–4 帧是 `TXTextLayout::updateDisplayString` / `didFinishLoadingIntoScene`。改文字会触发 `updateDisplayString` 重新排版，是**另一条会走到 `applyAllCaps` 的路径**。装载通过不等于编辑通过。

**风险等级：低。** 参数结构未变（都是同一套 style 定义），装载时已完整解析 8 处 id=12，编辑时读的是同一份数据。但既然 30 秒能测完，建议补上。

## 六、审核方未能核验的一项（如实标注）

**用户 Mac 上的已装模板，无法做哈希比对。**

- FCPX 模板实际路径：`~/Developer/Movies/Motion Templates.localized/Titles.localized/PSD 婚礼字幕/…`
- 审核沙箱只挂载：`/Volumes/摄影师工具箱128GB/未命名文件夹`、`/Volumes/NO NAME/128`
- → **无法证明已装的 T01 与 `build_staging/T01` 是同一份文件**

**可能的偏差**：
1. 已装的是最新构建 → 本次验收直接证明修复有效（最可能）
2. 已装的是某个中间版本（也含 id=12，但不完全等同）→ 仍能证明"这类修复有效"，但不能锁定到具体一次构建

**消除歧义的办法**（可选，非必须）：用最新构建重装一遍再测一次。但鉴于：
- 用户原报的坏版本 `14fa354d` **一碰就崩**
- 现在同名模板 `T01_领衔呈现_竖版` **不崩**
- 流水线当前产物 `全部大写` = 8 处（坏构建 = 0）

**三条合起来，修复有效的结论成立，无需强制重装。** 但若要"证据链完全无缝"，重装一次更稳。
