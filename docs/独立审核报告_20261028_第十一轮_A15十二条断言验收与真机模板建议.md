## 二、答复断言 6：**要求严格全局单例，请补 view 层协调器**

### 2.1 不是理论问题，已实测复现

| 操作 | 展开数 |
|---|---|
| 4 个图元同时 `_hovered=True` | **4** |
| 3 个图元同时 `setSelected(True)` | **3** |

**悬停**确实受物理限制（鼠标只有一个位置），但**选择**不受限：`QGraphicsScene` 默认可 Ctrl 多选与框选。用户框选一片文字层，就会同时展开多个徽章，重新造成覆盖——**这正是 A-15 要消除的现象，只是从"常态叠撞"变成"交互时叠撞"**。

### 2.2 开发方测试把违规写成了预期

`tests/test_a15_badge_collapse.py::test_06`：

```python
items[1][1]._hovered = True
expanded = [i for i, it in items if it._is_badge_expanded()]
assert len(expanded) == 2, "同时悬停两个时各自展开（使用层负责互斥）"
```

**该断言与我第 6 条规格方向相反。** 这不是实现偷懒，而是把未实现的部分写成了通过条件——比不写测试更危险，因为未来谁也不会再发现它。

### 2.3 判定与改法

**判定：断言 6 不通过。必须补 view 层协调器。**

- 这不是可选优化。**缺陷已从"视觉叠撞"转移为"交互叠撞"**，方案 1 的收益被部分抵消。
- 改动量估计：`on_selection_changed` / `hover_enter` 中，展开前先清除其他图元的 `_badge_expanded`，约 **10–15 行**。
- `test_06` 必须改为 `assert len(expanded) == 1`，并新增「多选 / 框选后仍只有一个展开」用例。
