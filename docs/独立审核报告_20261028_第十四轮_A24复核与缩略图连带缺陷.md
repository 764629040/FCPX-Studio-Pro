### 2.2 关键：8 层文字坐标是否跟着走（你提的正是这一点）

**先给机制**，`core/psd_parser.py` 中：

```
canvas_w, canvas_h = psd.size          # 画布尺寸取自 PSD 自身
center_x = canvas_w / 2                # 原点 = PSD 画布中心
center_y = canvas_h / 2
motion_x = layer_cx - center_x         # 位置 = 图层中心 − PSD 中心
```

也就是说，**文字 position 存的是「相对 PSD 中心」的偏移量，不是相对某个固定轴的绝对坐标**。修复前 comp 恒为 1920×1080，而 01 号 PSD 是 1080×1920，两者中心原点（960 vs 540）不重合，才出现整套偏移与错位。**comp 尺寸改成 PSD 尺寸后，两个中心自动重合，偏移量语义立刻变正确——不需要任何额外换算，也不会残留旧绝对值。**

**再用实测证死**（逐层比对，`position` 参数 id=101 / X 子参数，与源 PSD bbox 中心减 540）：

| Text 02 | 357–393 | 375.0 | **−165.0** | **−165.0** | 0.00 |
| Text 03 | 481–518 | 499.5 | **−40.5** | **−40.5** | 0.00 |
| Text 04 | 532–546 | 539.0 | **−1.0** | **−1.0** | 0.00 |
| Text 05 | 653–690 | 671.5 | **+131.5** | **+131.5** | 0.00 |
| Text 06 | 703–718 | 710.5 | **+170.5** | **+170.5** | 0.00 |

### 2.3 分布比例实测（回答「要不要测」）

**要测，而且这是判断「改完会不会产生新空白」的唯一硬指标。已经测了：**

| 指标（一律按「簇墨迹边缘」计） | 修复前（Round 13 实测） | 修复后（本轮实测） | 源 PSD 设计值 |
|---|---|---|---|
| 4 簇水平区间（占画布宽，左缘–右缘） | 16.0–20.3 / 25.1–28.2 / 34.0–37.3 / **80.5–83.9** % | **28.5–36.4 / 44.5–50.6 / 60.5–66.5 / 69.2–75.2** % | 与修复后**完全相同** |
| 首簇左留白 / 末簇右留白 | — | **28.5% / 24.8%** | 28.5% / 24.8% |
| 首簇→末簇中心跨度 | 约 1300 单位（超画布宽） | **429 单位 = 画布宽 39.7%** | 429 单位 = 39.7% |
| 最大簇间空隙（相邻簇边到边） | **829 单位 = 画布宽 43.2%** | **107 单位 = 画布宽 9.9%** | 107 单位 = 9.9% |
| `镇雄/CITY` 额外偏移 | **+800 单位（孤立右飘）** | **0.00 单位** | 0 |
| 文字墨迹总跨度（首簇左缘→末簇右缘） | — | **504 单位 = 画布宽 46.7%** | 504 单位 = 46.7% |

**结论三点：**

1. **不会产生新空白。** 最大簇间空隙从 **43.2%（829 单位）** 降到 **9.9%（107 单位）**，且这 107 单位正是源 PSD 里「新娘」与「新郎」两簇之间本来就有的间距，另外两处空隙为 88 单位（8.1%）与 29 单位（2.7%）——**全部是源设计固有间距，无一为新生的空洞**。
2. **文字不会「铺满」新画布，而这是正确的。** 墨迹总跨度只占画布宽 **46.7%**，左右留白 28.5% 与 24.8%——这是源 PSD 的原始设计。铺满反而错，忠实的 1:1 复现就是「不铺满」。
3. **你担心的方向是对的，但结论是安全的。** 若位置是相对固定轴存的绝对坐标，comp 从 1920 缩到 1080 后文字必然整体左移 420 单位并被裁掉。实测没有，因为原点跟着 PSD 走。

## 5. 新发现 A-29（P2）：竖版测试夹具内部不自洽，预览图变彩条乱码

### 5.1 现象

01 号模板产出的 `large.png` 不是任何正常画面，而是**红绿条纹乱码**（`docs/round14_evidence/B1_01_thumb_current_garbage.png`）。这不能用「拉伸」解释。

### 5.2 定位：夹具的背景层比画布还大

`psd-tools` 直读 `tests/data/vertical_wedding_9_16.psd`：

| 项 | 实测 |
|---|---|
| PSD 画布 | **1080 × 1920** |
| 背景层 `图层 0` bbox | **(0, 0, 1920, 1080)** ← **宽 1920 > 画布宽 1080** |
| 背景层实际像素 | 1920 × 1080，**纯黑**（均值 0，唯一色 1） |

背景层比画布横向多出 **840 px**。这是一个**画布尺寸被改过、但背景层没有同步缩放**的畸形 PSD。

### 5.3 对照实验（决定性）

对**同一个背景层**做两种合成：

| 合成方式 | 结果 | 唯一色数 | 均值 |
|---|---|---|---|
| `psd.composite()`（现行 `thumbnail.py` 使用） | **灰白/彩条噪点** | 2（且整体偏灰 111.56） | 111.56 |
| 手动按 bbox 贴图 + 裁剪到画布 | **纯黑** | 1 | 0.00 |

同一份像素数据，前者是错的。**结论：`psd-tools` 在图层 bbox 超出画布时读错像素，产出脏数据；`thumbnail.py` 直接把它缩放成 `large.png`，于是彩条进资源库。**

视觉证据：`docs/round14_evidence/B2_01_bgonly_composite_corrupt.png`（仅背景层合成——纯黑底却出现灰色带）。

### 5.4 定性与影响

- **测试夹具缺陷（主因）**：`vertical_wedding_9_16.psd` 内部不自洽。真实竖版 PSD 的背景层应与画布同尺寸，不会触发。
- **产品健壮性缺口（次因）**：`thumbnail.py` 盲信 `psd_obj.composite()`，未校验背景层 bbox 是否越界。建议加一道防线：合成前把超出画布的层按 bbox 裁剪，或改用逐层贴图合成。
- **额外风险**：这个畸形夹具是 A-24 **唯一的竖版验证依据**。它的不自洽会削弱验证可信度——虽然本轮 §2.2 的坐标核查与 comp 核查都不依赖背景层像素（只依赖 bbox 数值），结论不受影响，但**建议一并修正夹具**，并补一个背景层=画布尺寸的规范竖版样本。

### 5.5 更深一层：这份「竖版夹具」本来就是横版改的

逐层直读 bbox 后可以确认，畸形不是偶发错误，而是**画布被单方面改过、图层一概未动**的必然结果：

| 层 | bbox (left, top, right, bottom) | 说明 |
|---|---|---|
| `图层 0`（背景） | **(0, 0, 1920, 1080)** | **恰好等于 1920×1080，即横版原画布尺寸** |
| 领衔呈现 | (308, 388, 346, 563) | y 起 388 |
| lead the presentation | (357, 389, 393, 549) | y 起 389 |
| 新娘 朱永宏 | (481, 389, 518, 655) | y 止 655 |
| THE BRIDE | (532, 389, 546, 504) | — |
| 新郎 陈晗 | (653, 389, 690, 609) | — |
| THE GROOM | (703, 389, 718, 519) | — |
| 镇雄 | (747, 388, 784, 470) | — |
| CITY | (798, 389, 812, 438) | — |

三条独立线索指向同一结论：

1. **背景层尺寸正是 1920×1080**（横版画布），且贴在原点 (0,0)，右侧越界 **840 px**；
2. **8 层文字 y 全部落在 388–655**，纵向中心 ≈ **521**，恰好是 **1080 画布中心（540）**附近，而非 1920 画布中心（960）；
3. **文字 x 全部落在 308–812**，占 1920 宽的 16.0%–42.3%，正是横版左侧 Title 区的典型排布。

**故：该 PSD 原本是 1920×1080 横版，之后只把画布改成 1080×1920，所有图层未重新排布。它不是在竖版画幅下设计过的排版样本。**

**这一发现改变两件事：**

- **A-24 的结论不受影响**。A-24 判的是「comp 尺寸应等于 PSD 尺寸」，实测 01 号 comp 已为 1080×1920，坐标按 PSD 中心 1:1 归位（§2.2 八层误差全 0）。**管道修对了，这一点成立、可关闭。**
- **但「竖版版式合格」不能由这份夹具背书**。它产生的「文字挤在上部、下部 66% 空黑」是改画布未重排的残留，既不是模板 bug，也不是设计意图。**要验收竖版版式，必须另提供一份在 1080×1920 下真正排过版的 PSD。**

视觉示意：`docs/round14_evidence/A29_fixture_landscape_resized.png`。
