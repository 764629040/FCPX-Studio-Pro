3. A-30 深挖：你的根因说法与实测不符

3.1 你说「彩条源自 PSD 内部像素数据本身」

我逐层单独 composite() 检查了旧夹具的每一层：

没有任何一层自身含彩条像素——连那个 1920×1080 的越界背景层，单独合成也是 0/0。

3.2 那彩条从哪来

观察数值
整幅 psd.composite() 彩条42329 像素（2.04%）
彩条分布 bboxx[0..1079] y[221..1638]
背景层 bbox(0, 0, 1920, 1080)
彩条是否全在 y<1080 内否（最远到 y=1638，超出背景层 558 px）
彩条是否全在 x<1080 内是

已证事实（三条，均为实测）：

  1. 逐层单独 composite()：无任何一层含彩条像素（含越界背景层，0/0）；
  2. 整幅 psd.composite()：42329 个彩条像素，且越出背景层范围（y 最远 1638 > 1080）；
  3. 逐层贴图到画布：彩条 0/0。

由以上三条可判定：彩条不是任何一层的像素数据，而是整幅合成过程产生的伪影。

推断（非已证）：psd.composite() 在处理 1920 宽层写入 1080 宽画布时，疑似发生缓冲区跨行错位（row stride 不匹配）；逐层贴图时每层在自己 bbox 内合成、再裁到画布内，错位前提不成立，故彩条归零。审核方未深入 psd-tools 源码确认该机制，此处仅作解释性推断，不影响「逐层贴图可消除彩条」这一实测结论。

这一条很重要：根因不是「数据坏了」，是「合成器用错了」。 数据坏 → 只能换数据（你的原判）；合成器用错 → 换合成方式即可（实测可行）。

3.3 「裁剪不触发」——这点你说得对

crop_composite_to_canvas 只在 img.size != canvas 时生效。实测 composite() 返回尺寸恰好等于 1080×1920，所以 crop 永远走 return img, False，确实不触发。你这句判断准确，没有虚报。问题不在你判断错了，而在你只做了方案一，就把「方案二做不到」当成了结论。

5.2 必须同时完成的两件事

  1. generate_thumbnails_from_psd 的合成改用逐层贴图（保留 crop 作为尺寸兜底，保留检测器作诊断）；
  2. 背景层边缘延伸填充。

第 2 点是我原型暴露的瑕疵，必须如实告诉你：逐层贴图后，旧夹具背景层只有 1920×1080，裁到 1080×1920 画布后只覆盖上半部，导致下半部 13.1% 非透明、86.9% 空白。彩条是没了，但画面变成「上半有图、下半全黑」。

这不是逐层贴图方案的错，是背景层本身尺寸不足——真实畸形 PSD 也会这样。所以需要：当背景层 bbox 小于画布时，取其边缘像素向外延伸填充（或按画布尺寸纯色填充），保证整幅无空洞。
