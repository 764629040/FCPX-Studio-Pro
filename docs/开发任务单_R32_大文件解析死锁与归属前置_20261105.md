## 二、A-65 根因（P1，审核方已完整复现，含死锁实证）

### 2.1 结论先行

**这不是"某些 PSD 解析不出来"，而是「解析结果超过 64 KB 就必然卡死」的管道死锁。** 与 PSD 内容、图层类型、有没有图片**完全无关**——只跟输出体积有关。

### 2.2 源码位置

`FCPXStudioNative/Sources/FCPXStudio/Sockets/PSDParserSocket.swift`

```swift
36:  process.standardError = Pipe()          // ← stderr 建了管道，全程没有任何地方读它
39:  try process.run()
40:  process.waitUntilExit()                 // ← 先等子进程退出
42:  let data = pipe.fileHandleForReading.readDataToEndOfFile()   // ← 才读 stdout
```

**两个死锁源：**

1. **stdout 管道死锁（主因）**：`waitUntilExit()` 会阻塞等待子进程结束，但子进程写满 OS 管道缓冲区（macOS 默认 **64 KB**）后就会阻塞在 `write()` 上永远不退出 → 父进程永远等不到 → **双方永久互锁**。
2. **stderr 管道死锁（次因）**：第 36 行给 stderr 建了 `Pipe()` 却从不读取。子进程一旦往 stderr 写出超过缓冲区的内容（警告多、traceback 长时会触发），同样死锁。

### 2.3 实测证据（同一解析器，只换文件）

| 输入 | 桥接输出字节 | 结果 |
|---|---|---|
| `tests/data/four_state.psd` | **29 016 B** | ✅ 正常，读到 8 层 |
| `/mnt/local/128/字幕/纪实字幕.psd` | **107 704 B** | ❌ **RC=124 超时挂死**（不是报错，是永不返回） |

- 直接跑 `core/cli_bridge.py parse 纪实字幕.psd` → **EXIT=0，107 704 B，32 层齐全**。
  → **解析器本身完全正常，问题 100% 在 Swift 侧读取环节。**
- 用与 Swift 完全相同的时序（`p.wait()` 然后 `p.stdout.read()`）复现：小文件正常、大文件挂死 → **死锁确认**。
- 107 704 B ÷ 65 536 = 1.64 → 越过 64 KB 边界，与推断完全吻合。

### 2.4 附带发现：解析失败会显示「绿色成功」，这是必须一起修的第二个 bug

`InspectorView.swift:380-385`：

```swift
if !warnings.isEmpty {
    diagnosticsBox.stringValue = "⚠️ 诊断提示: " + warnings.joined(...)   // 橙色
} else {
    diagnosticsBox.stringValue = "✓ 矢量文字层完整提取，画幅适配正常"        // 绿色
    diagnosticsBox.textColor = 绿色
}
```

而 `parsePSD` 失败时返回 `.empty`（`PSDParserSocket.swift:12-14`）：

```swift
return PSDParseResult(width: 1920, height: 1080, aspectRatio: "16:9", resolutionSpec: "1080P",
                      layers: [], warnings: [], notes: [])     // warnings 是空数组
```

→ `warnings.isEmpty == true` → **显示绿色「✓ 矢量文字层完整提取」**。

**这正是用户截图里的样子**：画幅 `1920×1080 (16:9)`、绿色 `✓ 矢量文字层完整提取`、右侧图层表格全空、画布空白。

**用户看到的"显示不出来"是被伪装成成功的失败。** 这比普通报错更糟——它让用户以为文件没问题，进而怀疑自己的 PSD 有毛病。

### 2.5 修复要求

1. **改读取时序（必须）**，三种任选，推荐第一种：

```swift
// 方案一：先读完再等（最简单可靠）
try process.run()
let data = pipe.fileHandleForReading.readDataToEndOfFile()   // 先读，读到 EOF
process.waitUntilExit()

// 方案二：readToEnd()
try process.run()
let data = try pipe.fileHandleForReading.readToEnd() ?? Data()
process.waitUntilExit()

// 方案三：异步 readabilityHandler 累积（最稳，但代码多）
```

2. **stderr 必须一起读掉，不能只建管道不管**。最省事：把 stderr 也重定向到同一个 pipe（`process.standardError = pipe`），或 `pipe.fileHandleForReading.readDataToEndOfFile()` 后再读另一条；至少不能留一条永不读取的管道。

3. **加超时保护**：解析超过 N 秒（建议 60s，大 PSD 需要时间）主动终止并返回明确错误，**不许无限挂起**。当前挂死时用户看到的是界面卡住，体验极差。

4. **区分「解析失败」与「解析成功但无文本层」**：
   - `PSDParseResult` 增加 `isValid: Bool` / `failureReason: String?`；
   - 失败时 `warnings` **不能为空数组**，必须携带真实原因（如"解析超时"、"解析进程异常退出(exit code N)"、"输出过大/JSON 解析失败"）；
   - `InspectorView` 只有在 **`isValid == true` 且 `layers.count > 0`** 时才允许显示绿色「✓ 矢量文字层完整提取」；
   - 失败时显示 **红色**明确错误 + 可操作建议（如"该文件解析失败，请反馈此 PSD 以便定位"）。
5. **验证样本必须包含大文件**：拿 `/mnt/local/128/字幕/纪实字幕.psd`（107 704 B / 32 层）作为固定回归用例。**建议再加一个更大的（>500 KB 输出）**，把边界打穿。

## 三、A-66 归属信息前置（P2，UX 方向纠正）

### 3.1 用户的真实诉求（必须准确理解，别修错方向）

> 「大家全部都显示的是"移动到"，但我其实**要的不是它要移动到哪个位置**，非得移动到哪个位置，而是**要程序自动告诉我，它是在内置硬盘，是用户的还是系统内置的**这种类型。」

即：
- ✅ 要的是 **「告诉我它在哪」**（只读信息，一眼看懂）
- ❌ 不是 **「让我选要移到哪」**（操作入口，占了视觉主位）

R31 实际把「归属」列做出来了（🟡内置 / 🟢用户 / 🟣系统），但**「操作」列一整列全是「移动到…」下拉框**，视觉上完全压过了归属信息。用户扫一眼全是"移动到"，自然觉得"我要的不是这个"。

### 3.2 修复要求

1. **「操作」列默认不再是下拉框**。默认显示**状态文字**：
   - 内置级 → `🔒 只读`（纯文本）
   - 用户/系统级 → `—`（无操作）或 `⋯`（很小的次级按钮）
   - 迁移能力**保留**，但收进：**右键菜单** + 行末小 `⋯` 按钮弹出菜单。**不要用占满整列的下拉框。**
2. **归属列加强为"人话 + 路径"**，让人一眼知道在哪：
   - 显示形如 `🟡 内置` / `🟢 用户` / `🟣 系统`，并在**同一列或悬停 tooltip** 给出真实路径：
     - 内置 → `FCPX App 包内（MotionEffect.fxp/…/METemplates.localized）`
     - 用户 → `~/Movies/Motion Templates.localized`
     - 系统 → `/Library/Application Support/Final Cut Pro/Templates`
   - 「磁盘形态」列保持 R31 的两维度（实体 N MB / 软链接 0 占用），**不要退回到只剩一个维度**。
3. **列宽重排**：`归属` 加宽（≥120），`操作` 收窄（≤80），让归属信息在视觉上占主位。
4. **顶部筛选栏已有「归属：全部」下拉**，保留；建议再加一个**统计条**（如 `内置 4 · 用户 38 · 系统 0`），让用户不用滚动就能知道分布——这直接回应"我要程序告诉我它在哪"。
5. 迁移入口**功能不许删**（A-64 的需求仍在），只是**降级展示**。

### 3.3 A-66 验收判据

| # | 判据 | 判定标准 |
|---|---|---|
| 1 | 「操作」列默认形态 | **不再是整列下拉框**；内置级显示 `🔒 只读`，其它显示 `—`/`⋯` |
| 2 | 归属一眼可读 | 每一行能直接看出 内置/用户/系统，且能看到对应真实路径（列内或悬停） |
| 3 | 迁移仍可用 | 右键或 `⋯` 能调出「移动到 内置/用户/系统」，功能与 R31 一致 |
| 4 | 视觉主位 | 归属信息比操作入口更醒目（列宽 + 颜色 + 图标） |
| 5 | 统计条 | 顶部能一眼看到 内置/用户/系统 各多少个 |
