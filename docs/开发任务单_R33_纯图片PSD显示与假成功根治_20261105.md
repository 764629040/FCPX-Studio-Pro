## 〇、先纠正一个判断（重要，别修错方向）

用户观察是「随便拖一个没测过的 PSD 就没反应，只有它测过的那几个能出来」。

**这个归因不成立。审核方已排除白名单：**
- `FCPXStudioNative/Sources` 全量检索 `complex_layers` / `four_state` / `镇雄` / `whitelist` / `白名单` / `cache` → **全部 0 命中**
- `PSDImportPlanner` 无任何文件名过滤，任何 `.psd` 都会被 accepted
- 拖入本身是成功的（文件进了列表、被选中、被解析）

**真实机制是：这套程序在设计上只认「有文字图层的 PSD」。** 用户手上那些"能出来"的文件（`four_state.psd`、`commercial_4k.psd`）**恰好全是纯文字稿**；他随手拖的照片合成稿（`镇雄.psd`）**一层文字都没有**，于是被规则吃干、画布又只会画字 → 看起来就是"什么都没有"。

> **这是最关键的一处认知纠正**：不是"挑文件"，是"挑图层类型"。用户会一直撞，因为他实际业务素材大多是照片合成稿。**修 A-68 之前，别去找白名单，找不到的。**

## 二、根因（四段链路，全部实测）

### 2.1 实测数据：`镇雄.psd`

**底层真实结构**（psd_tools 直读）：

```
canvas 2848×1600   共 13 层
  1  图层 2        visible=True   pixel  全画布底图
  2..12（11 层）    visible=False  pixel  隐藏
 13  镇雄夜色      visible=True   pixel  ← 唯一可见的非底板层
文字层 = 0，分组 = 0
```

**产品解析输出**：

```
layer_count = 1        layers returned = 1
notes    = ["跳过默认底板图层: '图层 2'"]
warnings = []          ← 空
risk_assessment = None
```

**13 层 → 1 层。12 层消失，且 warnings 为空。**

### 2.2 四段链路逐条

**① 底板层被过滤**（`core/psd_parser.py:878-882`，正常设计）

```python
elif is_bg:
    disposition = "ignored"
    diagnostics_notes.append(f"跳过默认底板图层: '{name}'")   # ← 这条有记录
```

**② 11 个隐藏层被静默丢弃**（`core/psd_parser.py:886-888` ← **A-70 根因**）

```python
elif not layer.visible:
    disposition = "ignored"
    reason = f"隐藏未激活图层 ('{name}')，按设计规范忽略不导出"
    # ← 只写进 diagnosis_layers，不 append 到 notes，不 append 到 warnings
```

→ 与底板层形成**不对称**：底板写 note，隐藏层不写。`skip_layer_output` 后不进 output，**用户完全不知道有 11 层被吃了**。

**③ 唯一存活的位图层没有贴图**（`core/cli_bridge.py:26` ← **A-68 根因之一**）

```python
parsed = parse_psd_file(psd_path)     # ← 只传 1 个参数
```

而 `psd_parser.py:1167`：

```python
if extract_fallback_pngs and png_output_dir:   # ← 两者默认 False/None
```

→ **`extract_fallback_pngs` 默认 False、`png_output_dir` 默认 None，桥接层一个都没传**，所以 `png_path` 永远是 `None`，`fallback_png_info = {}`。

实测该层字段：`fallback_png_path = None`，只有 14×32 的列表小图标 `thumbnail_b64`。

→ **解析器文案说"安全降级为 32 位透明 RGBA 贴图"，但贴图从来没生成过。** 这是第二处"说了没做"。

**④ 画布只画文字，没有位图渲染路径**（`InfiniteCanvasView.swift:149-189` ← **A-68 根因之二，最致命**）

```swift
private func drawLayer(_ layer: LayerModel, isSelected: Bool, ctx: CGContext) {
    let lines = layer.text.components(separatedBy: "\n")     // ← 只取文字
    ...
    let astr = NSAttributedString(string: layer.text, attributes: attrs)
    astr.draw(in: textRect)                                  // ← 只画字
}
```

全文件检索 `NSImage` / `CGImage` / `draw(in:)` 图片路径 / `kind ==` 分支 → **位图绘制代码一行都没有**。

→ `镇雄夜色` 是位图层，`layer.text` 为空字符串 → 画一个空矩形 → **画布上什么都不出现**。

**⑤ 假成功**（`ParseDiagnostics.swift` 判定逻辑，R32 新写的纯函数 ← **A-69**）

判定只要求 `isValid && layers.count > 0 && warnings.isEmpty`：
- `isValid` = true（JSON 解析成功）
- `layers.count` = 1 > 0
- `warnings` = [] 空

→ **三条全中 → 绿色「✓ 矢量文字层完整提取，画幅适配正常」**，而 12 层已经没了。

### 2.3 对照组（证明"不是挑文件"）

| 文件 | 真实层数 | 文字层 | 产品返回 | 结果 |
|---|---|---|---|---|
| `four_state.psd` | 8 | **8（全文字）** | 8 | ✅ 画布有 4 层橙字 |
| `commercial_4k.psd` | 8 | **8（全文字）** | 8 | ✅ 正常 |
| `complex_layers.psd` | 5 | 4 文字 + 1 位图 | 5 | ✅ 文字有画，位图那层看不见（但行还在） |
| **`镇雄.psd`** | **13** | **0（全位图）** | **1** | ❌ **画布空 + 只剩 1 行** |

**结论：能出来的三个文件全是文字稿；出不来的那个一层文字都没有。与"是否测过"无关。**

## 三、修复要求

### 3.1 A-68 让位图真的看得见（P1）

**必须先决定产品定位，两种走法，二选一并在报告里写明选了哪个：**

**路线 A（推荐）· 位图层渲染成位图**
1. 桥接层传参：`parse_psd_file(psd_path, extract_fallback_pngs=True, png_output_dir=<临时目录>)`；
2. `InfiniteCanvasView.drawLayer` 增加位图分支：
   - `layer.kind == "pixel"` 且 `fallback_png_path` 可读 → `NSImage(contentsOfFile:)` → `image.draw(in: bbox)`；
   - 按 `layer.posX/posY/bbox/opacity` 定位缩放；
3. `LayerModel` 增加 `fallbackPngPath: String?` + `bbox` 字段，`PSDParserSocket` 把它读进来；
4. 大图性能：位图缓存（`NSCache`），避免每次 `draw` 都从磁盘读；缩放时用 `interpolation = .high`。

**路线 B（最小可用）· 铺一张整图预览做底**
1. 桥接层额外输出 `composite_preview_png`（`psd.composite()` 合成整图，缩放至 ≤2048px）；
2. 画布先画这张底图，再叠加文字层；
3. 优点：纯图片 PSD 立刻"能看见"；缺点：单层不可单独拖动/控制。

> **若时间紧，先上 B 保证"看得见"，再迭代 A。但 B 不能代替 A —— 用户最终要的是逐层可控。**

**另外必须修的（不分路线）：**
5. `psd_parser.py` 里"安全降级为 32 位透明 RGBA 贴图"的文案 —— **贴图没生成时不许这么写**。要么真生成，要么如实写"位图层未生成贴图，画布无法显示该层"。

### 3.2 A-69 假成功根治（P1，性质最严重）

**病根：诊断只看 `warnings` 空不空，不看"丢了多少层"。**

1. 引入**层数守恒断言**：`输入层数 == preserved + degraded + ignored`，且把 `ignored` 的明细**必须**透出到诊断；
2. 绿色「✓ 完整提取」的判定条件收紧为**全部满足**：
   - `isValid == true`
   - `warnings.isEmpty == true`
   - **`ignored_count == 0`** ← 新增硬条件
   - **`preserved_count + degraded_count >= 可见层数`**
3. 有 `ignored` 层时，诊断区**必须**显示（黄色或橙色）：
   > 「⚠️ 已忽略 12 层（11 个隐藏 + 1 个底板）。当前列表仅显示 1 个可见层。」
4. **绝对禁止**：`layers.count > 0` 就当成完整成功。1 层也是 > 0。

> 这是**同一根病根第三次出现**（R31 解析失败假绿 → R32 修掉 → R33 换路径复发）。R32 修的是"失败时别假绿"，没修"成功但丢层时别假绿"。**这次要求把"完整性"定义死，不许再用单点条件判断。**

### 3.3 A-70 隐藏层不许静默丢弃（P2）

1. `psd_parser.py:886` 隐藏层分支**必须** `append` 记录：
   ```python
   diagnostics_notes.append(f"跳过隐藏图层: '{name}'")
   ```
   与底板层保持对称；
2. 若隐藏层数量 ≥ 1，诊断区给出汇总：「本文件含 N 个隐藏图层，已按规范跳过」；
3. **提供开关（强烈建议）**：`显示隐藏图层` 复选框（默认关）。用户做验收/对照时经常需要看到隐藏层，否则永远不知道自己漏了什么。
