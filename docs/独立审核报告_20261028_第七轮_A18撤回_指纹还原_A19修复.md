## 4. A-14 裁定：**纠正审核方自身一处错误 → 不转设计变更，降级为 P3**

### 4.1 先更正我自己

第六轮及此前报告中，审核方称「画布无一键 1:1/100% 入口」。**该判断错误，特此更正。**

实测确认以下入口**存在且接线正确**：

```python
self.reset_btn = QPushButton("1:1")
self.reset_btn.clicked.connect(self._on_reset_100_clicked)   # L808-810
→ self.left_canvas.reset_100_percent()  /  self.right_canvas.reset_100_percent()   # L984-985
```

离屏实测：

| 操作 | 缩放比 |
|---|---|
| Fit（1400×900 并排）横版 1920×1080 | 0.3341（33.4%） |
| Fit 竖版 1080×1920 | 0.3952（39.5%） |
| Fit 方形 1080×1080 | 0.5605（56.0%） |
| **点「1:1」后（三种画幅均）** | **1.0000** |

说明：此前观察到的「约 44%」实际取决于窗口尺寸；在 1400×900 下竖版为 39.5%。
**缩放比本身不是缺陷，是窗口自适应结果。**

### 4.2 据此重新定性

A-14 的实质是：**在低缩放比下，左栏位图与右栏走不同渲染通道，清晰度不同**。
但用户**已有现成的 1:1 入口可以规避**，且 1:1 下渲染完全正确（第四轮已用 1:1 原生渲染核实「宏」字笔画完整）。

因此：

- **不属于「架构固有缺陷」**，也**不需要推翻架构做设计变更**；
- 属**使用引导问题**：用户不知道低缩放下不宜逐字判读。

### 4.3 建议（低成本，非架构改造）

按优先级，任选其一即可，**均不涉及渲染架构改动**：

1. **并排对照模式下若缩放 < 50%，在画布角标提示「低缩放下文字仅供定位，逐字核对请点 1:1」**（约 10 行 UI 代码）；
2. 或**并排对照模式默认以 1:1 打开**（复用现有 `reset_100_percent()`）；
3. 或仅在 `zoom_label` 低于 50% 时变色提示。

**审核方裁定：A-14 降级为 P3（使用引导），不转设计变更，不阻塞。**

## 5. A-15 裁定：**同意转设计变更，但措辞需修正**

### 5.1 几何事实（实测代码）

```python
b_w = max(110.0, len(badge_text) * 7.5 + 14)   # 最小宽 110px
b_h = 18.0
b_rect = QRectF(rect.left(), rect.top() - b_h - 4, b_w, b_h)   # 绘于包围盒上方
```

竖版图层行间距实测 11–14px，而徽章高 18px + 4px 间隙 = **22px**，**几何上确实装不下**。
这解释了「加宽反而使重叠从 5 组增至 6 组」的反证——**根因是高度方向，不是宽度方向**，
所以历次调宽度必然失败。该诊断成立。

### 5.2 但「固有属性」的措辞仍不严谨

徽章怎么画是**设计选择**，不是物理约束。至少存在多种不改架构的替代布局：

- 徽章移入右侧图层树 / 列表列，不画在画布上；
- 仅选中或悬停时显示徽章；
- 徽章改为画布外统一图例 + 图层内小色点标记；
- 竖版时徽章改纵向排列于包围盒右侧。

这些都不是「修补」，而是**换呈现方式**——所以「当前布局策略下无低成本解」成立，
「架构固有、无法修补」不成立。

### 5.3 裁定

**A-15 同意转设计变更立项**，由用户在产品层面决定采用哪种呈现方式。
定性维持 P2 观感项，**不阻塞核心链路**。措辞按 5.2 修正。

## 6. A-16 裁定：**建议现在启动，但不作为阻塞项**

### 6.1 为什么值得现在做

A-16 是当前**唯一无法由审核方验证**的项：无 AppKit 环境只能触达 `unverifiable` 一态，
`detected` / `font_missing` / 字形缺失三态在 Linux 下无法真实触发。
而开发方有 macOS 环境，且这是唯一能让「四态语义正确」变成可证事实的路径。

### 6.2 需交付的最小证据集（否则审核方无法核实）

1. **四态逐项截图**，每态一张，需包含：
   - `detected`：正常字体 + 覆盖率 100%
   - `font_missing`：明确声明一个系统未安装的字体名 + 该态徽章截图
   - `unverifiable`：无检测能力场景（可选，Linux 已证）
   - 字形缺失：字体存在但无中文字形（如纯英文字体渲染中文）+ 缺字标记截图
2. **字体清单**：`fc-list` 或 macOS 字体面板导出的可用字体名列表，用于证明「该字体确实不存在」
3. **每张截图对应的 PSD 文件名与图层名**
4. 建议同时给出该轮的指纹清单，使截图可追溯到具体代码版本

### 6.3 裁定

**启动，但列为「并行补证项」，不阻塞其他工作。**
理由：A-16 不影响核心链路可用性，但拖着会让「四态分化」长期停留在「代码看着对」的状态。
开发方既有环境，成本不高，宜早不宜迟。
