## 二、审核方独立实测数据

方法：ElementTree 精确解析（不用正则，避免 `uuid=` 中 `id` 子串假阳性）；长 id 定义为「纯数字且长度 ≥ 4」；冗余实例 = Σ(出现次数 − 1)。

### 2.1 三份 `.moti` 结构对照

| 文件 | 字节 | id 总数 | 唯一 id | 重复 key | 长id重复 key | 冗余实例 | target 数 |
|---|---|---|---|---|---|---|---|
| `build_staging/T01_领衔呈现_竖版.moti` | 247 979 | 1 604 | 242 | 95 | **38** | **44** | **49** |
| `build_staging/T23_含装饰_横版.moti` | 226 802 | 1 498 | 222 | 110 | **43** | **54** | **43** |
| `assets/reference_base.moti`（种子） | 248 462 | 1 599 | 241 | 95 | **38** | **44** | **65** |
| `128/FCPX_Studio_Assets_Test/…/01_领衔呈现.moti`（旧构建副本） | 245 537 | — | — | — | **18** | **150** | 49 |

**关键读数**：

1. **T01 与种子模板逐项相同**（38 key / 44 实例 / 重复分布完全一致，首项均为 `id=2000 x8`）→ 「deepcopy 继承」成立。
2. **T23 为 43 key / 54 实例，比种子多 5 个 key、10 个实例** → 接管方「38 个」的表述**只覆盖 T01**，对 T23 失效。
3. **旧构建副本为 18 key / 150 实例** → 重复长 id 数量**随构建版本剧烈波动**（18 / 38 / 43），说明该指标不是稳定结构量，而是构建过程的副产物。**任何单一数字（含「38」）都不能作为跨版本的固定基准。**

### 2.2 「零跨对象引用」成立，但「唯一被引用 3000107」是错的

对全部重复长 id 逐一统计其在引用型属性（`object` / `channel` / `style` / `target` 文本 等）中的出现次数：

| 文件 | 重复长id key | 被引用 key 数 | 引用总数 |
|---|---|---|---|
| T01 | 38 | **0** | **0** |
| T23 | 43 | **0** | **0** |
| ref_base | 38 | **0** | **0** |

`3000107` 实测：T01 出现 2 次、被引用 0 次；T23、ref_base 同样被引用 0 次。

**判定**：
- 「无跨对象引用」**成立**，且比接管方口径更干净（连 3000107 也是 0）。
- 「唯一被引用的是 3000107，但那是层内作用域引用」**属自我矛盾**：既称被引用、又称作用域内，而实测引用数为 0。该句应删除或改为「无任何引用」。
- 由此，「局部作用域重复」的**机制推断成立**，「无害」仍**未被证明**——缺的是真机加载，不是引用计数。

### 2.3 发布通道数：T01=49、T23=43、ref=65（接管方只报了 49）

| 文件 | 通道数 | 文本层数 | 校验式 |
|---|---|---|---|
| T01 | 49 | 8（`_build_review.json`） | 8 × 6 + 1(Graphics HDR) = **49** ✅ |
| T23 | 43 | 7（`_build_review.json`，另 media 2） | 7 × 6 + 1 = **43** ✅ |
| ref_base | 65 | — | 比 T01 多 16，已确认含 `Rotation 01–08`（8 个），其余待完整比对 |

`build_staging/_build_review.json` 原件印证：
- T01：`comp 1080x1920`、`层数 8 (text 8 + media 0)`、`缩略图 large 360x640 = 0.5625`
- T23：`comp 1920x1080`、`层数 9 (text 7 + media 2)`、`缩略图 large 640x360 = 1.7778`

**判定**：49 与 43 均由层数推导自洽，属**设计差异而非缺陷**。T23 缺 `03/05` 组、多 `09` 组，与其 7 层结构一致。接管方「49 通道」单点结论正确但**未区分两个模板**，易被误读为两者一致。

### 2.4 ozml 版本：接管方此处纠正是对的

三份文件根节点均为 `<ozml version="5.14">`。**Stage1 报告称 `version=2` 确为错误**，接管方该条纠正**成立并已由审核方独立确认**。

## 四、结论与处置

### 4.1 对「是否现在改 motion_builder.py 深层 id」的答复

**本轮不批准。** 理由三条：

1. **证据不足以支撑改动必要性**：核心论据「Apple 只有 2 个」不可验证（§3.1），「~19×」不稳健（§2.1）。在基准不明的前提下改代码，属于凭推断施工。
2. **改动风险与收益严重不对称**：该路径正是 R20 安装三步走 + FCPX 12.3 真机四项已闭环的同一代码路径（`motion_builder.py` deepcopy 段）。改动后必须重跑全量安装与真机验收，而审核方无 macOS 环境，无法兜底。
3. **无用户可感知的失效**：真机四项（导入/不闪退/不报错/预览图正确）已由用户实机确认通过。深层 id 重复未产生任何可观测故障。

### 4.2 登记新缺陷

| 编号 | 级别 | 描述 | 状态 |
|---|---|---|---|
| **A-37** | **P3** | 深层对象 id 继承性重复（T01 38 处、T23 43 处），源自 `reference_base.moti` deepcopy，无跨对象引用，缺真机加载铁证 | 待真机验证 |
| **A-38** | **P2** | 接管方声明「终验报告已写入 docs/」与「子代理 5 天无产物、最新停 10-27」均与文件系统实测不符（实际最新 10-29 17:03，报告不存在） | **成立，需开发侧更正** |
| **A-39** | **P3** | 接管方「唯一被引用的是 3000107」与其自身「零引用」结论矛盾，实测引用数为 0 | 成立，需更正表述 |

A-38 与 F-5（归因规范）属同一类：**结论可以成立，但陈述依据必须与文件系统/日志一致**。本轮已是此类瑕疵第四次出现。

### 4.3 对 F-3 的定性修正

原表述为「`tools/round.py` 收录 glob 遗漏」。实测为：**收录范围根本不含 `core/` 目录**（第 125 行仅 `tests/*.py`）。应定性为「收录规则设计缺失」，修正方案不是加通配符，而是**新增 `core/**/*.py` 与 `gui/**/*.py` 收录规则，并在清单中标注模块类型**。

### 4.4 唯一未闭环硬缺口（须用户手动）

FCPX 真机导入 + 检查器编辑发布参数。审核方与接管方均无法脚本驱动 FCPX 检查器。**必须由用户在 FCPX 中把模板拖入时间线、改一处 `Text 01`、拖动一次 `Position 01`，确认渲染无报错**，并回传 Titles 侧栏确认截图。
