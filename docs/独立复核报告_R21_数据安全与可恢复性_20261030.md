## 五、问题与观察项（不计缺陷）

### 观察 1：报告 §六第 7 条沿用了 R20 的错误归因

报告原文：

> `no_appkit` 模拟环境的 18 个 `ERROR at setup`（**AppKit 依赖的 setup 失败**）与本轮无关

**这一归因不准确，且已是第三次出现。**

R20 复核时我已抓取 `pytest_round20_no_appkit.log` 的原始报错，18 个 `ERROR at setup` 的真实根因是：

```
PermissionError: [Errno 17] File exists
```

即 **pytest 临时目录创建被沙箱代理拒绝**，与 AppKit 依赖无关。R20 我已指出一次，本轮 §六第 7 条仍写「AppKit 依赖的 setup 失败」。

**定性**：**报告归因瑕疵，非代码缺陷，不影响 R21 验收结论**。结论「与本轮无关」成立，但理由不对。

**要求**：今后凡涉及 `no_appkit` 日志的 error，必须抓 `E` 结尾那行的具体异常类型再定性，不得沿用「AppKit 被拦截」这一笼统说法。此项已在 R21 指令 §四判定树第 4 条明确要求，本轮未执行到位。

### 观察 2：指纹清单未收录两个新建源码模块

`core/template_versions.py`（约 160 行）与 `core/batch_runner.py` 未进入 `audit_inventory_r21.json`（82 = 78 + 4 个测试文件）。这意味着：

- 后续轮次无法用指纹证明这两个模块未被意外改动；
- 需确认 `tools/round.py inventory` 的收录规则是否遗漏 `core/` 下新增文件。

**定性**：工具收录范围问题，非缺陷。建议下一轮修正 `round.py` 的收录 glob，让新建源码文件自动入册。

### 观察 3：两项 GUI 接入未做

- T3：右键「历史版本」列表 UI
- T4：`_on_batch_export_all` 改造接入 `BatchRunner`，断点续跑入口

**定性**：**不构成缺陷**。T3 指令明确允许 GUI 后补；T4 侧重 core 能力与测试。但记为**后续项**，否则能力存在却无入口，用户实际用不到。
