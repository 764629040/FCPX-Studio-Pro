## 3. A-15 方案建议：**采用方案 1**

### 3.1 我的选择与理由

**推荐方案 1：常态显示 4px 色点，选中/悬停才展开完整徽章。**

理由：

1. **直接对症**——您已经定位根因在高度方向（徽章 18+4=22px > 竖版行距 11–14px）。
   色点高度 4px 远小于 11px 行距，从机制上消除叠撞，而不是靠调参绕开。
2. **信息不丢失**——颜色语义（绿/橙/红/黄）在色点上完整保留，扫一眼即知全图字体健康状况；
   详细文案按需展开。
3. **不改变架构**——仍是 `ConvertedLayerGraphicItem` 自绘，只改绘制策略，
   不动数据流、不动布局系统，符合「设计变更但不改架构」的定位。
4. **可回归**——可断言「竖版下 8 个图元色点矩形两两不相交」，把叠撞变成可测指标。

### 3.2 为什么不选方案 2（画布顶部集中列表）

集中列表把徽章移出画布，会导致**图层与状态的对应关系断裂**——
用户看到列表里"第 3 层缺字"，还得回头在画布上找第 3 层在哪。
竖版密集排布下这个映射成本很高，反而降低可判读性。

### 3.3 实施要点（若您批准）

| 项 | 内容 |
|---|---|
| 常态 | 4×4px 圆点，位于图层 bbox 右上角内侧，颜色同四态 |
| 展开条件 | 图层被选中（`isSelected`）或鼠标悬停（`setAcceptHoverEvents`） |
| 展开位置 | 保持现有「图层上方 + BADGE_GAP」逻辑 |
| 叠撞断言 | 断言竖版 8 层色点矩形两两不相交（当前徽章为 5 组相交） |
| 影响面 | 仅 `gui/canvas_view.py` 的 `paint()` 与 hover 事件 |

**待您确认后我再动手**——按规矩不擅自做设计变更。
