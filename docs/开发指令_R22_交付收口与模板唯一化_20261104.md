# 开发指令 R22：交付收口与模板唯一化

- 下发日期：2026-11-04
- 下发方：独立审核方
- 执行方：开发 AI
- 接收标准：见 §六「交付物与自证要求」
- 前置裁定：**审核方已否决 `motion_builder.py` 深层 id 改动**，本轮不得实施（理由见 §五）

---

## 零、分工原则（本轮新增，必须遵守）

**用户只做「成品审核」，不承担任何执行动作。**

具体含义：

1. **禁止向用户交付脚本、命令、工具让用户去跑。** 本轮所有诊断、清理、验证、构建动作，一律由开发 AI 自行执行。
2. **禁止要求用户手动删除模板、手动比对哈希、手动粘贴命令。** `~/Movies/Motion Templates.localized/` 下的清理动作由开发 AI 自己完成（有写权限即执行；无写权限时给出「一条可整段复制的终端命令」由审核方转交，而不是让用户手工逐个比对）。
3. **用户面前只呈现两种东西**：① 可直接拖进 FCPX 试用的最终成品；② 一段「你只需要拖进去看一眼」的最简验收说明。
4. **所有中间过程、脚本、日志、自证材料，交审核方，不经用户。**

上一轮审核方曾向用户交付 `.command` 诊断脚本，导致用户在 macOS 上遭遇执行权限拦截、无法运行。**该方式本轮废止。**

## 一、A-40（P1）：模板多版本残留 —— 最高优先级

### 1.1 缺陷事实（审核方独立取证）

| 文件 | 字节 | mtime | sha256(前16) | 重复长id | Media |
|---|---|---|---|---|---|
| `build_staging/T01_领衔呈现_竖版/T01_领衔呈现_竖版.moti` | 247 979 | 2026-10-28 12:14 | `4cf1db26d6f52a9a` | 38 key / 44 实例 | 空（该模板无媒体，正常） |
| `build_staging/T23_含装饰_横版/T23_含装饰_横版.moti` | 226 802 | 2026-10-28 12:14 | `d7520521418996f7` | 43 key / 54 实例 | 完好（箭头 741B、横线 116B） |
| `128/FCPX_Studio_Assets_Test/…/01_领衔呈现/01_领衔呈现.moti` | 245 537 | **2026-10-26 16:48** | `14fa354d5c35fa7e` | **18 key / 150 实例** | **`total 0` 完全为空** |

**用户实测反馈：FCPX 里看到「很多个版本」，且「有些版本一触碰就闪退」，因此暂停测试。**

### 1.2 判定

- 旧版（10-26）`Media/` 完全为空 + 冗余实例 150（新版 44 的 3.4 倍）→ **闪退高度嫌疑**。`Media` 为空导致 Motion/FCPX 打开即崩，这与 A-25 属同一失效模式。
- 多版本并存使此前「FCPX 四项通过」的**验收前提失效**：无法证明当时拖入的是正确版本。因此定级 **P1**，且**阻塞真机复验**。

### 1.3 必须完成的三项整改

**① 安装前去重（根因）**

在 `build_template_atomic` / 安装流程入口增加：安装前扫描目标模板目录树，若存在**同名或语义同源**的历史模板目录，先列出、判定、再处置。判定依据优先级：
1. `.moti` 的 sha256 是否与本次构建产物一致；
2. 若不一致，比对 `Media/` 是否为空、`.moti` mtime 是否为历史版本；
3. 输出「将保留 / 将移出」清单，写入报告。

**不得静默覆盖，也不得静默共存。**

**② 唯一性校验（安装后）**

安装完成后立即校验：
- 目标目录内该模板名的 `.moti` **有且仅有 1 个**；
- 其 sha256 **等于**本次构建产物的 sha256；
- `Media/` 文件数符合构建元数据 `_build_review.json` 的预期（T01 为 0，T23 为 2）。

任一不满足 → 视为安装失败，必须明确报错，不得返回成功。

**③ 历史版本处置**

旧版不得直接 `rmtree` 删除。移入项目内 `trash/` 或带 `.` 前缀的隐藏目录（与 F-4 的 A-36 整改同口径），并在报告中列出被移出目录的完整路径、字节、sha256、mtime。

### 1.4 关于用户 Mac 上的 `~/Movies/Motion Templates.localized/`

该路径不在审核方可访问范围（审核方仅挂载两个卷内子目录）。开发 AI 若在该路径有写权限，**自行执行清理**；若不能写入，则在报告中给出**一段可整段复制的终端命令**（含完整 `/Volumes/...` 或 `~/Movies/...` 绝对路径），由审核方转交，**不得要求用户自行逐个目录比对哈希**。

## 三、F-2：T4 GUI 接入（批量断点续跑）

- 能力现状：`core/batch_runner.py` 已实现 `.tmp` + `os.replace` 原子写、`resume_task` / `retry_failed`。
- 缺失：**批量导出未接入 GUI**。
- 要求：
  1. 批量导出改走 `BatchRunner`，进度条显示「已完成 / 总数 / 当前项」；

- 验收：构造一次人为中断（第 3 项抛异常），续跑后须只处理剩余项，不得重跑已完成项。以调用计数为证。

## 四、F-3：指纹收录规则修正（定义已更正）

### 4.1 原表述错误，现已更正

原写「`tools/round.py` 收录 glob 遗漏」。**实测：`tools/round.py` 第 125 行为 `glob(os.path.join(PROJECT_ROOT, "tests", "*.py"))`，收录范围根本不包含 `core/` 目录。** 这不是通配符遗漏，是**收录规则设计缺失**。82 = 78 基线 + 4 个测试文件，两个新源码模块（`template_versions.py`、`batch_runner.py`）**永远无法入册**。

### 4.2 要求

1. 新增 `core/**/*.py` 与 `gui/**/*.py` 收录规则；
2. 清单条目增加 `module_type` 字段（`core` / `gui` / `test` / `asset` / `doc`），便于分区核对；
3. **必须同时补测试**：若 `core/` 下新模块当前无对应测试，光改 glob 只会让 82 的构成变化而不增加实质保障，属假象。补测试后需给出「改前 / 改后」的条目数与新增测试通过数。

## 五、F-4：A-36 代码级整改

- 缺陷：`build_template_atomic` 的备份目录 `_bak_<timestamp>` 落在 FCPX 模板扫描树内，可能被 FCPX 识别为模板（幽灵模板风险）。
- 要求：新增 `backup_root` 参数（默认指向项目内非扫描路径），或将备份目录改为带 `.` 前缀的隐藏名。二者择一，报告中说明选择理由。
- 验收：安装后确认模板扫描树内**不存在**以 `_bak_` 开头的可见目录。

1. 产生该数值的**完整命令**；

**特别禁止**：把「没搜到」写成「不存在」。若检索未命中，必须同时给出**检索范围**（具体路径列表）和**检索命令**，并注明「在 X 范围内未命中，范围外未验证」。

## 七、明确禁止项

1. **不得修改 `motion_builder.py` 深层对象 id 生成逻辑。** 审核方裁定：证据不足（基准不可验证）、路径已闭环（R20 安装三步走 + FCPX 四项）、无用户可感知故障。硬改属过度工程。若坚持推进，须先提供 Apple 原生模板**实物**与可复现比对脚本，另行立项。
2. **不得向用户交付脚本或要求用户手工执行验证。**（见 §零）
3. **不得把开发报告写到审核方不可访问的卷。**（见 §6.1）
4. 不得静默覆盖已装模板，不得静默任其多版本共存。

## 八、验收口径（用户侧，最简）

用户只做一件事：把最终成品拖进 FCPX，确认以下四项。

1. 能导入（Titles 侧栏可见）
2. 不闪退
3. 无报错弹窗
4. 预览图是正常画面，不是彩条

此外**只有一条新增**：模板列表里**该模板只出现一个**，不再有多版本。

前四项此前已通过，但因多版本并存导致前提失效，须在 A-40 整改完成后**重做一次**。

## 九、优先级

```
P1  A-40 模板唯一化（去重 + 校验 + 历史处置）   ← 阻塞真机复验，最先做
P2  F-1 T3 GUI 接入
P2  F-2 T4 GUI 接入
P2  F-4 A-36 代码级整改
P2  F-3 指纹收录规则 + 补测试
P3  A-38 / A-39 表述更正（并入报告，不单独成轮）
禁止 motion_builder.py 深层 id 改动
```

完成后交审核方独立复核。审核方将复跑测试、复算指纹、核验模板唯一性，不以开发方日志结论替代独立验证。
