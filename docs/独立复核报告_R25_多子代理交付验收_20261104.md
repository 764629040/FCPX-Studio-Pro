## 五、A-47（P1）成立：C-10 缺字可见未真闭合

### 5.1 审核方实证

```bash
$ grep -n "marked_text" core/motion_builder.py
（空 —— 零命中）

$ grep -rn "marked_text" core/psd_parser.py
592:  marked_text: str = "",
648:  self.marked_text = marked_text
717:  "marked_text": self.marked_text,
859:  marked_text = ""
994:  # 真正缺字形时，用可见 tofu 标记替换缺失字符（marked_text），并由 highlight_missing_font
999:  marked_text = apply_missing_glyph_markers(text_content, missing_glyphs)
```

**结论：`marked_text` 只在 `psd_parser.py` 内部生成并存进诊断 JSON，`motion_builder.py` 里一次都没被引用。**

### 5.2 这意味着什么

C-10 的原始要求在任务单 §七：

> **缺字用可见标记（方框/问号）替代，诊断面板高亮。不得静默用默认字体顶上。**

现状：

| 层级 | 状态 |
|---|---|
| 数据层（psd_parser 生成 marked_text） | ✅ 已做，且有 `apply_missing_glyph_markers()` |
| `.moti` 输出层（写 marked_text 而非原始 text） | ❌ **未做** |
| GUI 诊断面板高亮 | ❌ **未做** |

**用户装上后看到的仍然是：缺字 → 原始文本 → FCPX 用默认字体顶上去 → 肉眼看不出来缺了字。**

也就是 C-10 想解决的"静默错误"**依然静默**，只是库里多了一个没人读的字段。

### 5.3 开发方的表述是否诚实

开发方在报告里写：「1 P2 数据层已修」。**这句话是诚实的**——他没说 C-10 完成了，只说数据层修了。

但主控报告的整体收口语气容易让人误读为 C 域 10 项全达标。**审核方在此明确定档：C-10 部分完成，不计入达标。**

### 5.4 为什么定 P1 而不是 P2

SA-4 定 P2，理由是"数据层已修"。审核方上调为 **P1**，理由：

1. C-10 在任务单 §十二「必保优先级」中列为**第 3 位**，明写"不可砍"
2. 它的失效模式是**静默错误**——用户不知道自己看到的是错的字体。这比"功能缺失"更危险
3. `.moti` 输出层现在走的是红线域（`motion_builder` 文本写出），而开发方在报告 §七自己写了"`.moti` 缺字层写原始 text 在红线域内，等你授权"

**即：开发方知道这条路要通过我授权才能走，他主动挂起了。这个处理方式是对的，但功能不能算完成。**

以后凡是写"实测 XX"，必须贴**完整命令行 + 原始输出**。不许写"实测为 XX"而不给证据。
