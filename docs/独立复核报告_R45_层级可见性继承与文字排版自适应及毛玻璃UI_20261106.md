  ```python
  def layer_is_effectively_visible(layer: Any) -> bool:
      if hasattr(layer, "is_visible") and callable(layer.is_visible):
          try:
              return bool(layer.is_visible())
          except Exception:
              pass
      cur = layer
      while cur is not None:
          if hasattr(cur, "visible") and not cur.visible:
              return False
          cur = getattr(cur, "parent", None)
      return True
  ```
- 在第 1009 行图层过滤核心逻辑处，将原有的判断修正为：
  `elif not layer_is_effectively_visible(layer):`

### 2. 文字排版自适应与漏字修复核查

#### (1) 根因与修复代码审查
审查 `FCPXStudioNative/Sources/FCPXStudio/Views/InfiniteCanvasView.swift`：
- **历史缺陷**：此前 CoreText 排版绘制机械依赖 PSD 元数据记录的固定位图包围盒 `psdBBox`（例如“被托付   的光”图层仅 1232pt 宽）。在 429pt 超大字号下，首行“被托付”3 个字自然展开需要约 1287pt 宽度。由于强行被限死在 1232pt，CoreText 将首行文字强制提前折行，导致“付”字被挤到第二行，而第二行末尾的“的光”因超出包围盒底部被直接裁剪吞掉。
- **自适应动态测量扩展**：
  在 `layerVisualSize(for:)`（第 484-489 行）与 `drawArtboardContent` 绘制分支（第 709-714 行）引入动态自适应测算：
  ```swift
  let neededSize = astr.boundingRect(
      with: CGSize(width: max(bw * 2.0, 4000), height: 10000),
      options: [.usesLineFragmentOrigin, .usesFontLeading]
  ).size
  let drawW = max(bw, ceil(neededSize.width) + 24)
  let drawH = max(bh, ceil(neededSize.height) + 24)
  let textRect = CGRect(x: -drawW / 2, y: -drawH / 2, width: drawW, height: drawH)
  ```
  在原始包围盒宽度与 CoreText 实际所需排版宽度之间取上确界，并加上安全边距，彻底杜绝折行与裁剪。

#### (2) 尺寸断言实测
在 Swift 原生直证套件中实测该大字号图层：
- 原始 psdBBox 尺寸：1232 × 892
- CoreText 实测需要空间：1287.0 × 1202.0
- 自适应计算视觉尺寸：**1311.0 × 1226.0**（`drawW >= 1287.0` 且 `drawH >= 1202.0`）
- 5 个汉字（“被”、“托”、“付”、“的”、“光”）完整排布于两行，无任何字符被吞没。

**复核判定**：**PASS**
