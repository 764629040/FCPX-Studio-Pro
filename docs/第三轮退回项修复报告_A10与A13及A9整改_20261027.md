## 1. A-10 无 AppKit 平台误报「字体未安装」

### 1.1 根因（与审核指认一致）

`core/psd_parser.py` 中判定顺序为「先判 `is_font_available`，再判 `unverifiable`」：

```python
if not is_font_available:          # 无 AppKit 时此处为 False -> 抢先命中
    detection_status = "font_missing"
elif glyph_cov["status"] == "unverifiable":
    detection_status = "unverifiable"
```

而 `check_font_availability()` 在 `import AppKit` 失败时 `except: pass` 后 `return False`，
把「无法检测」与「未安装」压成同一个 `False`。于是无 AppKit 平台必然短路到 `font_missing`，
与该文件第 96-97 行自述契约（`unverifiable`）相反。

**这是跨平台缺陷，不是环境噪声**——审核方在 Linux 实测的 `1 failed` 正由此产生。

### 1.2 修复

把「检测能力」与「字体是否安装」拆成两件事：

```python
def appkit_available() -> bool:
    """仅有能力判定，与某字体是否安装无关"""

def check_font_availability_status(font_name) -> str:
    """三态：available / missing / unverifiable
       关键契约：无检测能力必须返回 unverifiable，绝不能返回 missing"""
    if not appkit_available():
        return "unverifiable"
    ...
```

保留布尔接口兼容，改为包装三态：

```python
def check_font_availability(font_name) -> bool:
    return check_font_availability_status(font_name) == "available"
```

判定顺序改为按 availability 三态分流：

```python
if font_availability == "unverifiable" or glyph_cov["status"] == "unverifiable":
    detection_status = "unverifiable"
elif font_availability == "missing":
    detection_status = "font_missing"
else:
    detection_status = "missing_fallback"
```

告警文案同步分化，`unverifiable` 分支写「无法检测…缺字风险未知…待复核」，不再出现「未安装」。

### 1.3 验证

|---|---|
| macOS（有 AppKit） | 69 passed / 0 failed / 退出码 **0** |
| 模拟无 AppKit | **67 passed / 0 failed / 2 skipped / 退出码 0** |

审核方原报的 `1 failed`（`test_four_state_fixture_covers_multiple_states`）已消除。

无 AppKit 下文本图层状态集合实测为 `{'unverifiable'}`，`font_missing` 出现 0 次。

## 2. A-13 左栏整幅错位

### 2.1 根因（与审核指认一致）

图元位置以画板中心为参照系：

```python
qt_x = cx - center_x     # center_x = artboard_w / 2.0
qt_y = cy - center_y
```

而 `set_artboard_resolution()` 只重建画板框，**不重算既有图元**：

```python
def set_artboard_resolution(self, width, height):
    self.artboard_w = width
    self.artboard_h = height
    self._rebuild_artboard()
    self.fit_artboard_in_view()      # 旧实现到此为止
```

因此「先加载图层、后设分辨率」时图元仍按旧参照系定位，整幅错位。

### 2.2 修复

```python
def set_artboard_resolution(self, width, height):
    self.artboard_w = width
    self.artboard_h = height
    self._rebuild_artboard()
    self._relayout_items()      # 新增：按新参照系重算所有既有图元
    self.fit_artboard_in_view()

def _relayout_items(self):
    for item in getattr(self, "items_map", {}).values():
        if hasattr(item, "artboard_w"): item.artboard_w = self.artboard_w
        if hasattr(item, "artboard_h"): item.artboard_h = self.artboard_h
        if hasattr(item, "update_geometry_from_info"):
            item.update_geometry_from_info()      # 右栏
        elif hasattr(item, "update_geometry"):
            item.update_geometry()                # 左栏
```

### 2.3 验证

按审核方复现顺序（**先 `load_layers`、后 `set_artboard_resolution`**）：

| 夹具 | 图元数 | 左右位置不一致 | 最大偏移 |
|---|---|---|---|
| 竖版 1080×1920 | 8 | **0** | 0.0 px |
| 横版 1920×1080 | 5 | **0** | 0.0 px |

竖版逐层实测（左右完全相等）：

| 图层 | 左栏位置 | 右栏位置 |
|---|---|---|
| 领衔呈现 | (-213.0, -484.5) | (-213.0, -484.5) |
| lead the presentation | (-165.0, -491.0) | (-165.0, -491.0) |
| 新娘朱永宏 | (-40.5, -438.0) | (-40.5, -438.0) |
| THE BRIDE | (-1.0, -513.5) | (-1.0, -513.5) |

**反证**：临时禁用 `_relayout_items()` 后重跑同一路径，竖版 **8 个图元全部错位，最大偏移 420.0 px**——与审核观察的"约 200px"同向（竖版更严重）。证明该修复确是缺陷对应的解，而非巧合。

## 3. A-9 裁决要求的两项整改

### 3.1 ① 两条链路开关口径统一

**问题**：`parse_psd_file` 默认 `extract_thumbnails=True`（第 594 行），主窗口亦传 `True`；
但 `generate_conversion_diagnosis_report` 固定写死 `extract_thumbnails=False`。
同一份 PSD 在诊断链路与画布链路下图层可呈现性不同。

**修复**：

```python
def generate_conversion_diagnosis_report(
    psd_path, extract_fallback_pngs=False, png_output_dir=None,
    extract_thumbnails: bool = True,      # 新增，与 parse_psd_file 默认值对齐
) -> Dict[str, Any]:
```

**回归断言**：`inspect.signature` 对比两函数 `extract_thumbnails` 默认值必须相等；
且默认调用诊断链路时确能产出切片。

### 3.2 ② 三类占位原因文案拆分

**问题**：`gui/canvas_view.py` 原先把三种情况统一写成「空图层 / 无像素内容」，
无法区分「图层组」「真空层」「切片解码失败」。

**修复**：新增 `placeholder_reason` 字段，按语义优先级判定：

| 原因 | 触发条件 | 文案 |
|---|---|---|
| `group` | `layer_type == "group"` | 📁 图层组容器 / 无独立像素 |
| `empty_layer` | `is_empty == True` | ⚠️ 真空图层 / 尺寸为零或无有效像素 |
| `no_slice` | 无 `original_slice_bytes` | 🖼 未生成原稿切片 / 请开启 extract_thumbnails |
| `decode_failed` | 有字节但 `QPixmap.loadFromData` 失败 | ❌ 原稿切片解码失败 / 数据可能损坏 |
| `None` | 有真实切片 | （正常渲染，不进入占位分支） |

**回归断言**：四种原因互不相同（`len(set(reasons)) == 4`）；
真实切片不得触发任何占位分支。

### 3.3 关于「不加实时绘制兜底」

已遵守：**未添加**「切片缺失时回退实时绘制文字」。占位分支只显示文字说明，
不以矢量文本冒充原始栅格，避免重新引入字体度量偏差。
