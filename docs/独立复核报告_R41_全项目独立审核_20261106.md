## 三、发现的缺陷

### A-72（P1，新）——「显示隐藏图层」开关 UI 完全失效（A-70 功能未真正落地）

**现象**：勾选 Inspector 顶部「显示隐藏图层（默认关）」复选框，图层列表**不会**从 1 层展开到 12 层。

**根因（调用链早退）**：

```swift
// MainWindowController.swift:220
inspectorView.onHiddenLayersChanged = { [weak self] on in
    self?.setIncludeHiddenLayers(on)
}

// :350  R33/A-70 切换开关 → 重新解析
private func setIncludeHiddenLayers(_ on: Bool) {
    guard includeHiddenLayers != on else { return }
    includeHiddenLayers = on
    let row = psdTableView?.selectedRow ?? -1
    if row >= 0 {
        selectPsdFile(at: row)      // ← 转调
    }
}

// :359
private func selectPsdFile(at row: Int) {
    guard row >= 0, row < psdFiles.count else { return }
    let path = psdFiles[row]
    if currentPsdPath == path && !canvasView.layers.isEmpty { return }   // ← 362 行：必然早退
    ...
}
```

**必然性论证**：勾选开关时，`currentPsdPath` 必然等于当前文件路径（刚从它解析出来），且 `canvasView.layers` 非空（刚解析出 1 层）。两个条件同时成立 → 第 362 行 `return` → **永不发起重解析，开关恒为无效操作**。

**为何未被发现**：R33 harness 只测了 Python 层 `parse_psd_file(include_hidden=True)`（日志仅 2 处 `include_hidden`），**未覆盖 Swift 开关回调链路**。故 A-70 被标 Closed，但用户实际点开关毫无反应。

**影响**：A-70 的"可查看隐藏层"承诺对用户不可兑现。用户在 `镇雄.psd` 上勾选开关将看不到任何变化，会二次投诉"还是没反应"。

**修复要求**：
1. `setIncludeHiddenLayers` 不得依赖 `selectPsdFile` 的早退逻辑，应直接触发解析（或先 `canvasView.layers = []` / `currentPsdPath = nil` 再转调；推荐抽出 `parseCurrentFile(force: Bool)`）；
2. 必须补一条 Swift Harness 断言：**模拟开关翻转 → 断言解析被再次调用且层数由 1 变为 12**（正向与反向各一次）；
3. 该断言必须进入 `tools/round.py verify` 守护，防止再次回归。

### A-73（P2，新）—— `include_hidden=True` 时统计口径与列表自相矛盾

**现象**：`include_hidden=True` 实测返回 `layers=12`（12 层全部带 PNG），但同一份结果里：

```
output_layer_count = 1
skipped_layer_count = 12
ignored_count = 12
degraded_count = 1
preserved_count = 0
```

**影响**：若 UI 用这套计数字段生成诊断文案，用户会看到"**已忽略 12 层 / 仅显示 1 个可见层**"，而画布与列表**实际显示了 12 层**。信息自相矛盾，属于**假告警**（与"假成功"同源，方向相反）。

**修复要求**：`include_hidden=True` 时，`output_layer_count` 应为 12、`ignored_count` 应只统计真正被丢弃的底板层（1）。守恒断言需按 `include_hidden` 分口径分别成立，并补对应单测。

### A-74（P2，新）—— 台账纪律三项硬伤

| # | 问题 | 实测证据 |
|---|---|---|
| a | **轮次编号重复** | 台账存在 **2 处** `## 第三十九轮`：第 3665 行（`（R33）`）与第 3735 行（`（R33 独立审核与总指挥终审）`） |
| b | **项目内指针滞后 126 行** | 指针声明 `行数 3872 / sha256 2417a2ef…`；主清单实际 **3998 行 / sha256 e7747a48…**；且指针注释停在"含第四十二轮 R36"，**R37/R38/R39 三轮均未同步** |
| c | **R40 完全未登记** | `grep -c "R40" 主清单` = **0**；无"第四十六轮"章节，而 R40 开发报告 + 62 项 harness + `audit_inventory_native_r40.json` 均已产出 |

**影响**：指针是多方（开发 AI / 审核方 / 用户）判断"哪份是最新版"的唯一依据。指针滞后 126 行 + R40 未登记，正是历史上反复出现的"读到旧副本、基于失效基线施工"事故的**直接复因**。

**修复要求**：
1. 合并或重编号两处「第三十九轮」；
2. 指针行数/sha/轮次一次性对齐到主清单实况（3998 行），并新增**断言**：指针声明的行数与 sha 必须与主清单一致，否则 `tools/round.py verify` 直接判红；
3. 补登 R40（第四十六轮），并在台账体例中强制"**未登记台账 = 未交付**"。

### A-75（P3，新）—— R39 台账存在超出证据能力的绝对化断言

**原文**：「引擎二对标嘉星战役（R37 / R38 / R39）达成 **100% 完完全全的全功能覆盖与超越**！」

**问题**：该结论要求"覆盖并超越 `/Applications/嘉星插件管理 2.app` 的全部功能"。审核环境无 macOS、无该应用，**无法核验竞品功能全集**，"100%/完完全全/超越"三重绝对词均无证据支撑。此类表述会误导用户认为对标战役已收兵，实际可能仍有未识别的功能缺口。

**修复要求**：改为可核验表述，例如「本轮已落地 X/Y/Z 三项能力（附 harness 断言数），剩余差异项见 §N」，禁止使用无法证伪的绝对化措辞。

### A-76（P1 风险堆积，流程级）—— 5 个 P1 连续 7 轮零真机闭环

自 R33 起至 R39，台账累积 5 项 P1 全部挂"**待人工真机确认**"：

```
A-65 大文件管道死锁    —— 待真机
A-68 纯图片画布显示    —— 待真机
A-71 文字位置/挤压     —— 待真机
D-73 画布智能吸附      —— 待真机
D-74 图层锁定与隐藏    —— 待真机
```

**风险**：这 5 项全部落在**同一条交互主链路**（拖入 PSD → 画布渲染 → 选中图层 → 拖动/锁定）。一旦真机验收在任一环节发现系统性问题，需一次性回滚 7 轮改动，定位成本极高。且 A-72 已证明：**未经真机交互验证的 UI 开关，恰是最容易失效且最容易被 harness 漏掉的部分**。

**要求**：真机验收不得再整体后置。至少 A-72 修复后必须立即做一次"开关翻转"真机点验，不得再次挂起。

## 五、审核能力边界（诚实声明）

本次审核**无法覆盖**以下项，开发方与用户不应据本报告推断其已通过：

1. **Swift 源码实际编译验证**——环境无 swift/swiftc，无法独立复现构建，只能核验二进制结构与源码是否存在；
2. **macOS 真机交互**——画布拖动、吸附手感、锁定徽标视觉、LUT 分屏、音频试听、FCPX 拖拽导入等**全部无法实测**；
3. **codesign 签名有效性验证**——无 codesign 工具，只能确认 `LC_CODE_SIGNATURE` 结构存在且 magic 合法，不能确认证书链与 Gatekeeper 放行；
4. **嘉星插件管理 2.app 功能对标**——无该应用，A-75 所述"100% 覆盖与超越"无法证伪；
5. **A-72 修复前的开关行为**——基于源码静态推导（早退条件必然成立），未在真机点验确认。
