## 二、本轮任务：补齐 4 个缺口

**严格按 P0 → P1 → P2 顺序做，前一项不通过不进下一项。**

### T1（P1）磁盘空间预检

**缺口**：全仓无 `shutil.disk_usage`，无空间不足检查。当前在磁盘将满时会写入到一半失败，留下残件。

**要求**：

1. 在 `build_template_atomic` 的 pre-flight 区（现有检查 1、2 之后，第 543 行附近）新增检查 3；
2. 估算待写数据量 = PSD 源文件大小 + 预计缩略图（按 `width*height*4` 粗估）+ 安全余量；
3. 用 `shutil.disk_usage(ancestor).free` 判断，不足时抛新增异常类 `StorageSpaceError`（继承现有存储异常的基类，保持风格一致）；
4. **余量阈值写进常量**，不要散落魔数。建议 `MIN_FREE_MARGIN = 200 * 1024 * 1024`（200MB）+ 估算量的 1.5 倍；
5. 异常信息需给出「需要 X MB / 可用 Y MB」的具体数字。

**验收**：

- 单测：用 monkeypatch 把 `shutil.disk_usage` 的 `free` 改成极小值，断言抛 `StorageSpaceError`；
- 单测：正常空间下不抛（回归保护）；
- 二者都要能在我复跑 `pytest tests/ -q` 时通过。

### T2（P1）重名模板冲突预检

**缺口**：当前 `backup_existing=True` 会**静默**把已有目录 `os.rename` 成 `_bak_<ts>` 然后覆盖。用户不会被告知"这个模板已存在，我要覆盖它"。这是数据丢失风险点——用户可能覆盖掉自己精心调过的版本而不自知。

**要求**：

1. 在 pre-flight 阶段检测 `output_dir` 是否已存在且非空；
2. 新增参数 `on_conflict`，取值 `"backup"`（默认，保持现有行为）/ `"abort"` / `"ask"`；
   - `"abort"`：直接抛 `TemplateConflictError`，不写任何东西；
   - `"ask"`：**由调用方注入回调**，不要在这里直接弹 Qt 对话框（core 层不得依赖 GUI）；
3. `core` 层只负责**抛出可判定的冲突信号**，UI 决定怎么问；
4. `gui/main_window.py` 里绑定：保存到模板时若冲突，弹确认框（覆盖 / 取消），默认「取消」；
5. **不得改变默认行为**——不传参时仍走 `backup`，保证既有调用与既有测试不受影响。

**验收**：

- 单测：`on_conflict="abort"` 时目标已存在 → 抛 `TemplateConflictError`，且**目标目录原样未动**（断言 mtime 和文件列表不变）；
- 单测：默认 `backup` 时目标已存在 → 正常备份+覆盖，旧行为不回归；
- 单测：`on_conflict="ask"` 时回调被调用一次，回调返回 False 则不写入。

### T3（P2）模板版本管理（列表 / 恢复 / 保留策略）

**缺口**：只有 `_bak_<ts>` 产生，**没有任何消费它的代码**——不能列出历史版本、不能一键恢复、也没有保留策略。备份目录会无限堆积。

**要求**：

1. 新增 `core/template_versions.py`，提供：
   - `list_versions(template_dir) -> List[VersionInfo]`：扫描同级 `{name}_bak_*`，按时间倒序返回 `{path, timestamp, size, moti_ok}`；
   - `restore_version(template_dir, version_path)`：把当前目录先备份（`{name}_bak_<now>`），再把指定版本原子换回；
   - `prune_versions(template_dir, keep=5)`：只保留最近 N 个，其余移入回收目录（**不要直接 `rmtree`**，先移到 `{name}_trash_*` 再删，保留可救回窗口）；
2. **恢复必须走备份**，不允许"直接覆盖当前"——即恢复前必须先备份现行版本；
3. `moti_ok` 字段：检查该版本内 `.moti` 是否存在且 XML 可解析，用于列表里标注"该版本可能已损坏"；
4. GUI 最小接入：右键模板 →「历史版本」，弹出列表，可恢复、可删除。**无 GUI 也要先有 core 能力和测试**，GUI 可后补。

**验收**：

- 单测：造 3 个版本 → `list_versions` 返回 3 条且倒序正确；
- 单测：`restore_version` 后，内容等于目标版本，且**多出一个新备份**（证明恢复前有备份）；
- 单测：`prune_versions(keep=2)` 后剩 2 个，被删的进了回收目录而非直接消失；
- 单测：`moti_ok` 对一个故意损坏的 `.moti` 返回 False。

### T4（P2）批量处理断点续跑

**缺口**：批量处理多个 PSD 时，中途失败只有一句失败报告文案（`gui/main_window.py` 第 621 行附近），**没有 checkpoint，没有续跑入口**。50 个文件挂在第 37 个，只能从头再来。

**要求**：

1. 新增 `core/batch_runner.py`，任务态落盘为 `.batch_state.json`（写在**输出目录**，不写 128 卷）：
   - 字段：`task_id`、`items[]`（每项：源路径、目标路径、状态 `pending/done/failed`、错误摘要、时间戳）、`created_at`、`updated_at`；
2. **每处理完一项立即写盘**（不要攒到最后一次性写），保证断电也有进度；
3. 提供 `resume_task(state_path)`：只跑 `pending` 和 `failed` 的项，`done` 的跳过；
4. 提供 `retry_failed(state_path)`：只重试 `failed`；
5. 状态文件写入用「写临时文件 + 原子替换」，避免写一半损坏状态；
6. 幂等性：同一项重复执行不得产生重复产物（以目标目录是否已完整存在为准）。

**验收**：

- 单测：造 5 个任务，第 3 个注入失败 → 状态文件里 2 done / 1 failed / 2 pending；
- 单测：`resume_task` 后只剩失败项被重试，`done` 的没被重复处理（用计数器断言调用次数）；
- 单测：状态文件在每项完成后都已更新（模拟中断后重新加载，能看到已完成项）；
- 单测：原子写——写过程中抛异常，原状态文件不被破坏。
