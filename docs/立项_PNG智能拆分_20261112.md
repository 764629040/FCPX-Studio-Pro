# PNG 智能拆分 · 立项单（2026-11-12）

> 质控侧下发，仅立范围与验收，不指定实现手段。执行侧回《实现方案》后再评审。

## 0. 一页结论

- **要做什么**：只有一张成品图（PNG/JPG），没有 PSD 源文件时，把它拆成四类独立透明层，进现有设计器，最终生成能在 FCPX 里改文本的 `.moti` 模板。
- **不做什么**：不做矢量文字层（不 OCR、不重建可编辑文本）；不输出 PSD；不引入数 GB 的本地 AI 权重；不动 `.moti` 写回五值口径。
- **分几期**：P1 最小可用（四类分层 + 进设计器 + 出模板）→ P2 遮挡补全 → P3 批量。
- **P1 交付形态**：一条命令行入口 + 一份分层清单 JSON + 每层透明 PNG + 设计器可读入。

## 1. 问题与目标

现有主链路是：**PSD 源文件 → 设计器拆层 → 生成 Motion 标题模板（.moti）→ 在 FCPX 里改文本 / X / Y / 可见 / 锁定**。写回只认五值，且文本必须落在中文参数链（对象→文本，见 `MotiDocumentParser.swift` 文本读取路径）。

缺口是入口：用户手上常常只有**成品图**（宣传海报、封面、字幕条），没有分层源文件。没有层，就没有可独立调整的对象，也就生不出能改的模板。

**P1 目标（可判定）**：给定一张 1080×1920 成品图，跑完后得到 ≥4 个透明层（至少 1 个 OBJECT、1 个 TEXT、1 个 BACKGROUND），层名可读，设计器能读入并生成 `.moti`，在 FCPX 里改文本生效。

## 2. 与现有能力的关系

| 维度 | PSD 链路（现有） | PNG 链路（本单新增） |
|---|---|---|
| 输入 | 分层源文件 | 单张成品图 |
| 图层来源 | PSD 真实图层 | 算法推断分层 |
| 文字 | **真文字层**，可读 text/字体/字号/颜色 | **文字的图片**，只是位图，读不到文本内容 |
| 面板可改 | 文本 / X / Y / 可见 / 锁定 | 同上五值（文本改的是「显示用的文字层」位图，见 §8 边界） |
| 依赖 | 无外部模型 | 见 §4 路线 |

关键提醒：外部 AI 分层工具（如 tangchengliao/image-to-layered-psd）输出的是栅格层/智能对象层，**它的「TEXT」是文字的图片，不是可编辑文本层**。我们设计器靠真文字层取文案，因此 PNG 链路的产品定位必须写清：**「长得对、能整体挪、但文字改不了内容」**。这一条要在 UI 上明示，不许让用户以为能改字。

## 3. 四类层口径（借用并改写自外部 Skill 的四类分层规则）

分层原则：**按「是否需要独立调整」分层，不按「视觉上像不像一整块」分层**。

| 类 | 判定 | 必做 | 禁止 |
|---|---|---|---|
| OBJECT | 会被单独移动/缩放/替换的主体（人像、产品、logo 主体） | 主体轮廓完整、边缘带 1-2px 羽化 | 把主体和它的投影/光晕拆开 |
| TEXT | 文字区域（含艺术字、竖排字） | 整段文字为一个层，保留原像素 | 逐字拆层；尝试识别成可编辑文本 |
| ELEMENT | 装饰件、图标、光效碎片、分隔线、边框 | 可独立移动的逐个成层 | 把背景纹理误判成元素 |
| BACKGROUND | 去掉以上三类后的底图 | 补全被遮挡区域（见 §5） | 缺口不补直接交付 |

层名规则：`<类>_<序号>_<可读名>`，例如 `OBJECT_01_产品`、`TEXT_01_主标题`、`ELEMENT_03_金色边框`、`BACKGROUND`。只用 ASCII 类的英文大写 + 中文可读名，避免路径里的空格与全角符号。

## 4. 技术路线取舍

| 路线 | 体积 | 速度 | 离线 | 效果风险 | 结论 |
|---|---|---|---|---|---|
| A 本地 AI 分割模型（SAM 类） | 权重数百 MB–数 GB | 首次加载慢，单图秒级–十秒级 | 可用 | 边缘好，但分类（文本/元素）仍要后处理 | **否**：撞体积红线，用户已明确拒绝 |
| B 云端分割 API | 0 | 依赖网络，单图秒级 | 不可用 | 稳定但要上传用户素材 | **仅作可选旁路**，不作默认 |
| C 传统图像算法（前景分离 + 连通域 + 边缘/显著性 + 颜色聚类） | 与现有依赖同量级（MB 内） | 单图百毫秒级 | 可用 | 复杂背景会漏分、文字与背景同色时难切 | **P1 推荐**：先做能用的 60 分，再用规则兜 |

落地口径：
- **红线**：新增依赖体积 ≤ 版本包体增量上限（P1 立项暂定 ≤ 20MB，具体值由执行侧实测后报，不许口头承诺）。
- P1 允许「分不准」，但**不许假装分准**：拿不准的区域必须落在 BACKGROUND 并给出 `low_confidence` 标记，由用户在面板里手动合并/拆开。
- 任何路线都要给出「单图耗时」实测，不许写「很快」。

## 5. 遮挡补全（分层后能不能动的关键）

问题：某层被挪走后，露出它原来遮住的地方，背景是个洞。

| 方案 | 说明 | 成本 | 优先级 |
|---|---|---|---|
| 1 延展填色 | 用边缘像素向外推/镜像延展填洞 | 低，纯 CPU | **P1** |
| 2 邻域内容感知（patch 匹配） | 在背景层里找相似块补洞 | 中 | P2 |
| 3 生成式补全 | 模型补洞 | 高，撞体积红线 | 不立项 |

不做的后果：用户一挪层就露洞，模板在 FCPX 里一动就穿帮 —— 等于白拆。所以 P2 必须在 P1 之后紧跟，不许无限推后。

## 6. 输出物规格

```
<输出目录>/
  分层清单.json        # 每层：类、序号、可读名、bbox、透明 PNG 路径、置信度
  layers/
    OBJECT_01_产品.png      # 透明底，原分辨率，不缩
    TEXT_01_主标题.png
    ELEMENT_03_金色边框.png
    BACKGROUND.png          # 已补洞
```

- 全部 PNG：8bit RGBA，透明底，与源图同分辨率，不做缩放。
- 目录名与文件名不含空格、全角符号、emoji。
- 体积目标：四类层 PNG 总和 ≤ 源图 PNG 的 2.5 倍（写实测，不写估算）。

## 7. 验收标准（逐条可判）

1. 指定测试图 A（文字 + 主体 + 装饰 + 渐变背景）跑通，输出 ≥4 层，四类齐全。
2. 每层单独叠在棋盘格上无「黑边/白边/半透明毛边」；OBJECT 边缘 1-2px 羽化可见。
3. 挪走 OBJECT 后，BACKGROUND 无可见空洞（P1 用延展填色即算过；P2 判据另定）。
4. 分层清单 JSON 字段齐全，`low_confidence` 有则必标。
5. 设计器能读入输出目录 → 生成 `.moti` → 在 FCPX 里改文本、改 X/Y 生效。
6. 体积与耗时：新增依赖增量 ≤ 立项值；单图耗时实测并写进报告。
7. 不新增超过 20MB 的第三方依赖，不引入任何模型权重文件。
8. 全程不启动 FCPX 做自动化测试（人工只在最后一步验证）。

## 8. 不在范围

- 不做矢量文字层 OCR / 文字重建（TEXT 层永远是位图）。
- 不输出 PSD，不改 `.moti` 写回模块（`MotiWriteBack.swift` 一个字节不动）。
- 不接云端服务做默认路径；不新增联网行为。
- 不引入 AI 模型权重（体积红线）。
- 不动现有 PSD 链路、不动只读态、不动 harness。
- 本单不封版（v1.7 另立）。

## 9. 分期与依赖

| 期 | 内容 | 交付物 |
|---|---|---|
| P1 | 四类分层 + 延展填色 + 清单 + 设计器读入 | 命令入口、10 张测试图分层结果、验收报告 |
| P2 | 邻域内容感知补全 + 面板手动合并/拆分 | 补全前后对照图、漏分率统计 |
| P3 | 批量（≥20 张）与失败重试、断点续跑 | 批处理日志与耗时表 |

依赖：P1 必须先定「分层清单 JSON 字段契约」，否则 P2 无法回归。

## 10. 风险与退回条件

- 退回 1：分层结果四类不齐或层名带空格/全角，判不合格。
- 退回 2：BACKGROUND 有明显空洞就交付，判不合格。
- 退回 3：偷偷加了模型权重或联网，判不合格。
- 退回 4：只报「分层看着不错」，拿不出可复现命令与 10 张测试图结果，判不合格。

## 11. 一句话口径

**成品图进来、四类层出去、补洞补上、设计器能读、FCPX 能改；文字能挪不能改，这句要写在界面上。**
