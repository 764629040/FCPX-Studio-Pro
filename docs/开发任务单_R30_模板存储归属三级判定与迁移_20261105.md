## 二、根因（已定位到行号，且比表面现象更严重）

### 2.1 当前只扫了「用户级」一个目录，另外两级根本没进列表

`core/symlink_manager.py:9`：

```python
DEFAULT_SYSTEM_MOTION_DIR = os.path.expanduser("~/Movies/Motion Templates.localized")
```

- `SymlinkManager.system_root` 被写死为 `~/Movies/Motion Templates.localized`；
- `get_installed_plugins()`（`symlink_manager.py:127-160`）**只 `os.listdir` 这一个目录**；
- Swift 侧 `SymlinkSocket.swift:19` 同样写死 `"~/Movies/Motion Templates.localized"`，`listInstalled()` 也只读这一个 `sysCat`。

**结论：`~/Movies/Motion Templates.localized` 在 FCPX 的语义里是「用户安装」级目录（你给的第 1 条路径），但代码把它命名为 `system_root`、并把它当「系统盘」来展示。**

### 2.2 判定逻辑只有「是不是软链接」一个布尔值，然后被当成「存储位置」显示

`SymlinkSocket.swift:19` / `symlink_manager.py:138` 只计算 `isSymlink`，`AssetHubView.swift:189`：

```swift
let str = p.isSymlink ? "🟢 外置软链接 (0系统盘占用)" : "⚠️ 系统内置盘 (占用存储)"
```

- 非软链接 → 一律显示「系统内置盘」。**但这个"非软链接"只代表"它没被外链到外置盘"，完全不代表它是系统级/App 内置。**
- 于是用户看到的红色 ⚠ 一片，实际含义是「这些模板都在内置硬盘上、没外链出去」，**而不是**「这些模板装在 FCPX App 包里」。
- **名词错位是本轮的核心问题**：`system_root` 这个名字、以及「系统内置盘」这个文案，共同制造了误导。

### 2.3 用户给的第 2 条路径（App 包内 METemplates）从未被扫描

`/Applications/Final Cut Pro Creator Studio.app/Contents/PlugIns/MediaProviders/MotionEffect.fxp/Contents/Resources/METemplates.localized/Titles.localized`

全项目检索 `METemplates` / `Final Cut Pro.app/Contents` → **0 处命中**。App 内置模板既不在列表里，也无法被识别。

## 三、必须先确认的一件事：真实 FCPX 是「三级」，但你只给了两条路径

你自己的 FCPX 截图（第 2 张）里，「存储位置」列有 **三种** 值、三种底色：

| FCPX 显示 | 底色 | 真实磁盘位置（FCPX 官方语义） |
|---|---|---|
| **内置** | 黄 | `/Applications/Final Cut Pro.app/Contents/PlugIns/.../METemplates.localized/<分类>` ← **你给的第 2 条** |
| **用户** | 绿 | `~/Movies/Motion Templates.localized/<分类>` ← **你给的第 1 条** |
| **系统** | 紫 | `/Library/Application Support/Final Cut Pro/Templates/<分类>` ← **你没给，截图里有** |

→ **需求按三级做，不是两级。** 第 3 条「系统」路径请开发 AI 按上表标准位置实现，并在真机上先 `ls` 确认存在再启用。

> ⚠️ 注意你机器上的 App 名是 `Final Cut Pro Creator Studio.app`，不是标准 `Final Cut Pro.app`。开发时**不要写死 App 名**，要按下面的方式动态定位。

## 四、修复要求（给开发 AI）

### 4.1 A-63 归属判定（P1）

1. **建立三级根目录表**（不要写死单一 root）：

```swift
enum TemplateTier {
    case builtin   // 内置：App 包内 METemplates.localized
    case user      // 用户：~/Movies/Motion Templates.localized
    case system    // 系统：/Library/Application Support/Final Cut Pro/Templates
}
```

2. **App 包动态定位**（不要写死 `Final Cut Pro.app`）：

   - 优先用 `NSWorkspace.shared.urlForApplication(withBundleIdentifier: "com.apple.FinalCut")`；
   - 取不到则遍历 `/Applications` 下匹配 `*.app` 且包内含 `Contents/PlugIns/MediaProviders/MotionEffect.fxp` 的候选；
   - 找到后拼 `Contents/PlugIns/MediaProviders/MotionEffect.fxp/Contents/Resources/METemplates.localized/<分类>`；
   - **找不到就优雅降级**：该级显示为空/「未检测到 FCPX」，**不许崩溃、不许整表清空**。

3. **扫描合并三级**：三个根目录各扫一遍，同一 `名称` 出现在多级时**全部列出并各自标注层级**（不要悄悄去重，用户需要知道自己装了几份、哪份生效）。

4. **「存储位置」列改为双维度显示**（这是关键，两个维度必须分开，不能混成一个字符串）：

   - **维度 A · 归属层级**：`内置` / `用户` / `系统`（对应黄/绿/紫）
   - **维度 B · 磁盘形态**：`实体（占用系统盘 N MB）` / `软链接 → 外置盘（0 占用）`

   建议把列拆成两列：「归属」+「磁盘形态」，或在一列内用 `用户 · 软链接(0占用)` 这种复合文案。**但必须两个信息都在**，不能像现在这样用 B 的信息冒充 A。

5. **统一术语**（消除误导源头）：

   - `system_root` 这类命名改为 `userMotionRoot` / `userTierRoot`；
   - Python 侧 `DEFAULT_SYSTEM_MOTION_DIR` 同步改名或加注释说明它是**用户级**目录；
   - 全项目检索并清理把 `~/Movies/...` 称为「系统盘」的文案。
   - ⚠️ 注意：改名会动到 `core/symlink_manager.py`，**该文件不在 110 项红线内，可以改**；但 `core/motion_builder.py` **仍然不许碰**。

6. **排序与筛选**：列表支持按归属层级排序/筛选（至少内置/用户/系统三档可见），方便用户清点。

### 4.2 A-64 跨层级迁移（P2）

1. 对**单条**选中项提供「移动到 …」下拉/菜单：`内置 / 用户 / 系统`（当前所在级置灰）。
2. 迁移 = 先 `moveItem` 到目标级同名目录 → 成功后再删源；**失败必须回滚，绝不允许出现"两边都没有"或"两份都在"**。
3. 目标已存在同名项 → **不覆盖**，弹冲突提示（覆盖/跳过/改名三选一）。
4. 迁移过程要有进度提示（大模板如 1.7 GB，会明显耗时），**主线程不可阻塞**（沿用现有 `DispatchQueue.global` + 回主线程刷新的模式）。
5. 迁移完成后自动 `refreshList()` 并定位到刚移动的那一项，给出明确结果提示。

### 4.3 ⚠️ 必须正视的风险（写进实现，不许绕过）

**往「内置」级迁移 = 写入 App 包内部，有两个真实风险：**

1. **签名失效**：`/Applications/.../Contents/` 是已签名包体，写入任何文件都会破坏代码签名密封。轻则 Gatekeeper 再次拦截，**重则 FCPX 启动失败或内置模板全部不加载**。用户机器上装的是 `Final Cut Pro Creator Studio.app`（非官方 App Store 版可能性大），风险更高。
2. **权限**：`/Applications` 与 `/Library` 通常属于 admin/root，当前用户 `mrhuang` 若无写权限，`moveItem` 会直接失败。需要 `sudo` 或提权 —— **而 GUI 里静默提权是不可接受的**。

**因此实现要求：**

- 迁移到「内置」级前，**必须**弹二次确认，明确写出：「此操作会修改 FCPX 应用程序包内部文件，可能导致应用签名失效、FCPX 无法启动或模板不加载。是否继续？」并在文案里给出「更安全的替代：移动到『系统』级」。
- 迁移到「系统」级需要写权限时，**明确提示需要管理员授权**，不要在失败后只弹一句"搬家失败"。
- 迁移前**自动备份源目录到 `~/Movies/FCPX_Studio_Backup/<时间戳>/`**（或至少记录可回滚清单），并在 UI 提供「撤销上次迁移」。
- **默认推荐路径**：把 `用户 ↔ 系统` 作为主推（两者都可正常写、不破坏签名）；`内置` 级**默认只读展示**，迁移作为高级选项并带强警告。

> 这一条不是我在阻拦需求。你的两条路径我都照做，只是「往 App 包里写」这件事在 macOS 上有客观副作用，必须让你在点之前知道。若你确认「就要能搬进 App 包，签名失效也认」，在任务单回一句「内置级可写，接受签名风险」，我就放开默认只读限制。
