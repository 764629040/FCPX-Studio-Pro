## 六、A-15 方案 1 批准与断言规格

### 6.1 几何实测（`vertical_wedding_9_16.psd` / `four_state.psd`，画布 1080×1920）

徽章几何取自 `gui/canvas_view.py` 源码：

```
b_h = 18.0
b_rect = QRectF(rect.left(), rect.top() - b_h - 4, b_w, b_h)
b_w = max(110.0, len(badge_text) * 7.5 + 14)     # 主体层
```

**关键：徽章有一个 110 单位的最小宽度下限，而竖版相邻列的实测水平间隙只有 11–14 单位。**

**叠撞 4 / 7 对。** 与四态同框截图中右栏徽章连成一片的观感一致。

### 6.2 审核方对第八轮根因表述的更正

第八轮我写"根因在高度方向 22px > 行距 11–14px"。**该表述方向不准确**：

- `rotation = 90°` 的图元（`lead the`、`THE BRIDE`、`THE GROOM`、`CITY`）经 `setRotation(90)` 后，徽章的 18 单位厚度落在**水平**方向；
- `rotation = 0°` 的图元（领衔呈现、新娘、新郎、镇雄）徽章为**横向 110 单位宽**，而列宽仅 14–38 单位，必然压住 4–8 个邻列。

**准确表述**：根因是**徽章固定尺寸（最小 110 宽 / 18 厚）与竖版 11–14 单位的列间距不匹配**，横向（宽度与厚度）与纵向同时失配，横向失配量级更大（110 vs 11–14，约 8 倍）。

结论方向不变（调宽度/字号无效、需改交互形态），但**论据已修正**。

### 6.3 批准

**批准方案 1：常态显示 4 单位色点，选中或悬停时展开完整徽章文本。**

量化依据：4 单位色点的水平占用 = 4 单位 < 最小间隙 11 单位，**在最密列上仍保有 ≥3.5 单位净空**，从几何上必然消除叠撞；且四色语义可原样复用，不新增状态。

### 6.4 断言规格（建议开发方据此实现，供下轮验收）

**折叠态（默认）必须满足：**

1. 色点尺寸 4×4，以图层 bbox **中心**为锚点，随图元旋转（不得用 `rect.left()` 作锚点）；
2. 任意两个可见文字层的**色点外接框互不相交**；
3. 色点外接框**不得与任何其他图层的文字 bbox 相交**；
4. 在上述两条基础上，最小净空 **≥ 3 单位**（以 `four_state.psd` 最小间隙 11 单位计算，留 1.5 单位余量）；
5. 断言需在 `vertical_wedding_9_16.psd` 与 `four_state.psd` 两个夹具上**同时通过**。

**交互态（选中 / 悬停）允许重叠**，但须满足：

6. 展开仅对**单个**图层生效（同一时刻最多一个展开）；
