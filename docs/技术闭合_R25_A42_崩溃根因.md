```python
    data = open(path, "rb").read().decode("utf-8", "replace")
    return len(re.findall(r'name="全部大写"', data))

BAD  = "docs/r24_evidence/legacy_bad_build_14fa354d/01_领衔呈现/01_领衔呈现.moti"

```

## 3. 修复逻辑（core/motion_builder.py ~L348-366）

在 `build_moti` 为每个文本层组装 `<style>` 时，**无条件保证 `name="全部大写"` / `id="12"` 参数存在**：若缺失则补建，并插入到 `id="81"` 之后。原文如下：

```python
                    # 确保全部大写 (id="12") 参数无条件完整存在，杜绝 Motion TXTextLayout::applyAllCaps 段错误崩溃
                    all_caps_p = style.find("parameter[@id=\"12\"]")
                    if all_caps_p is None:
                        all_caps_p = ET.Element("parameter", {
                            "name": "全部大写",
                            "id": "12",
                            "flags": "8589934608",
                            "default": "0",
                            "value": "0"
                        })
                        p81_idx = None
                        for s_idx, sp in enumerate(style):
                            if sp.tag == "parameter" and sp.attrib.get("id") == "81":
                                p81_idx = s_idx
                                break
                        if p81_idx is not None:
                            style.insert(p81_idx + 1, all_caps_p)
                        else:
                            style.append(all_caps_p)
```

- 注入规则：缺失才补（`if all_caps_p is None`），不改变任何已有结构。
- 顺序保证：`id="12"` 紧邻 `id="81"` 之后（与好构建实测顺序 `'81','12'` 一致）。
- **未改动** deep-id 生成逻辑（layer / scenenode / style / para 的 id 仍由原型深拷贝 + 规律 id 生成），仅补齐缺失参数。
- 该修复在 `tests/test_r25_a46_all_caps.py` 中被守护；见 §5 与 docs/r25_evidence/test_goes_red.txt 的“红/绿”证明。

## 4. 完整因果链（Causal Chain）

```
早期 01_领衔呈现 构建（sha 14fa354d…）
   └─ 文本层 <style> 中【缺失 name="全部大写" / id="12" 参数】（实测计数 = 0）
        └─ Motion/FCPX 加载该模板时，TXTextLayout::applyAllCaps(__CFString*) 读取该参数
             └─ OZChannel::getValueAsDouble(CMTime const&, double) const 命中空指针（参数不存在 → channel 为 null）
                  └─ EXC_BAD_ACCESS → SIGSEGV
                       └─ Final Cut Pro 在模板加载阶段崩溃（“一碰闪退”）
```

### 4.1 崩溃日志实证（docs/r24_evidence/crash_logs_r24.txt，2026-11-02 那次）

**原始记录片段（行 9-36）：**

```
  TIME            : 2026-11-02 23:07:33.00 +0800
  EXC             : EXC_BAD_ACCESS
  SIGNAL          : SIGSEGV

    # 0 OZChannel::getValueAsDouble(CMTime const&, double) const <== template-load
    # 1 OZChannel::getValueAsInt(CMTime const&, double) const <== template-load
    # 2 TXTextLayout::applyAllCaps(__CFString*) <== template-load
    # 3 TXTextLayout::updateDisplayString(CMTime const&) <== template-load
    # 4 TXTextLayout::didFinishLoadingIntoScene() <== template-load
```

关键证据点（与因果链一一对应）：
- `SIGNAL : SIGSEGV` / `EXC : EXC_BAD_ACCESS` —— 空指针段错误。
- `in_template_load: True` —— 崩溃发生在**模板加载**阶段（与“一碰就闪退”吻合）。
- `# 2 TXTextLayout::applyAllCaps` —— 全部大写处理入口。
- `# 0 OZChannel::getValueAsDouble` —— 在读取全部大写参数时命中空指针（channel 为 null）。

## 6. A-44 归因结论（Attribution）

### 6.1 11-02 崩溃 → 归因于早期 `01_领衔呈现` 构建（sha `14fa354d…`）
- 该早期构建即 `docs/r24_evidence/legacy_bad_build_14fa354d/01_领衔呈现/01_领衔呈现.moti`：
  - 文本层 `<style>` 中 `全部大写`(id="12") 计数 == **0**（见 §2.1 / §2.3 / §2.4）。
  - 其 `Media/` 目录为空（坏构建特征：无降级贴图）。
- 该构建与 11-02 的 SIGSEGV 崩溃日志（TXTextLayout::applyAllCaps → OZChannel::getValueAsDouble 空指针，in_template_load=True）**机理完全吻合**，故 11-02 崩溃可明确归属于此早期构建缺陷。
- 现状：`core/motion_builder.py` 已在构建管线中补齐 `id="12"`（见 §3），新构建文本层 `全部大写` 计数 == 文本层数（T01 实测 8/8），该缺陷经管线修复。

### 6.2 11-03 ×3 SIGABRT 崩溃 → 与模板无关（保留原判）
- docs/r24_evidence/crash_logs_r24.txt 中 2026-11-03 的三次崩溃（17:40:24 / 17:41:31 / 17:44:43）均为 **SIGABRT**（EXC_CRASH），且 `in_template_load: False`。
- 三次崩溃的故障线程栈均命中 Core Data 目录层：
  **原始记录片段（以 17:40:24 为例，行 38-64）：**
  ```

    SIGNAL          : SIGABRT
    in_template_load: False
    # 0 __pthread_kill
    # 1 pthread_kill
    # 2 abort
    ...
    #15 -[DSBridge objectWithID:store:error:]
    #16 -[FFCatalogStore objectWithID:error:]
    #17 -[FFMediaEventProject objectFromID:]
  ```
  （另两次 17:41:31、17:44:43 栈帧同源，均为 `-[FFCatalogStore objectWithID:error:]`。）
- 结论：**11-03 的 3 次 SIGABRT 发生在 Core Data 目录（FFCatalogStore / DSBridge）查询路径上，与标题模板的 `全部大写` 缺失缺陷无关**，保留 R24 的既定判断，不在 A-42 修复范围内。
