用户的归因「只认测过的文件」**不成立**。审核方已排除白名单，开发方复查同样 0 命中。真实机制是：**本程序在设计上只认「有文字图层的 PSD」**。能出画面的 `four_state.psd`/`commercial_4k.psd` 全是纯文字稿；随手拖的照片合成稿一层文字都没有，被规则过滤、画布又只会画字 → 表现为「什么都没有」。本轮按此机制修复，不是去找白名单。

## 一、A-68 位图真的看得见（P1）—— 选路线 A

**路线选择：路线 A（位图层逐层渲染为位图）+ 底板预览兜底。** 理由：用户最终要的是逐层可控（任务单原话），B 不能代替 A。额外把「底部整幅像素层」提升为画布底板预览（`background_preview`），覆盖纯照片稿没有命名「背景」层的场景——这是 A 路线的必要补强，不是另起一套。

### 1.1 修复点（全部落在 Swift 原生壳 + core，未只改 gui）

| 链路 | 修改 |
|---|---|
| ③ 桥接不传参 | `core/cli_bridge.py` 改为 `parse_psd_file(psd_path, extract_fallback_pngs=True, png_output_dir=media_output_dir(psd_path), include_hidden=...)`；并关掉 `extract_thumbnails`（缩略图 Swift 端不用，旧逻辑白做 44s 拖慢大图） |
| ④ 画布无位图路径 | `InfiniteCanvasView.swift` 增加位图分支：`layer.kind == "fallback_png"` 且 `fallbackPngPath` 可读 → `NSImage(contentsOfFile:)` → 按 `posX/posY/scale/opacity/rotation` 定位缩放绘制；`NSCache` 位图缓存（按 sha 缓存，避免每次 draw 读盘），`interpolation = .high`；`backgroundPreview` 作最底层整图底 |
| 字段贯通 | `LayerModel.swift` 新增 `fallbackPngPath` / `bbox` / `visible`；`PSDParserSocket.swift` 读入 `fallback_png_path` / `psd_bbox` / `visible` / `background_preview` |
| 文案 | 删掉「安全降级为 32 位透明 RGBA 贴图」的空话；贴图确未生成时如实写「位图层未生成贴图，画布无法显示该层」（本案已真生成，不触发） |

### 1.2 修复前/后实测（同一镇雄结构样本，离屏渲染取中央画板像素统计）

| 指标 | 旧路径（只画字） | 新路径（位图渲染） |
|---|---|---|
| 非背景像素占比 nonBg | **0.0327**（接近全黑） | **0.5930**（真实出画面） |
| 像素标准差 stddev | 8.4 | 49.2 |
| 渲染产出 | `docs/r33_evidence/a68_unseen_old_blank`（旧逻辑对照，全黑） | `docs/r33_evidence/a68_zhenxiong_render.png`（镇雄街景可见） |

> 旧路径对照：在 harness 内用同一份解析结果，仅走旧 `drawLayer` 文字分支，nonBg=0.0327，证明「画布空」是渲染缺失而非样本问题。新路径 nonBg=0.5930，画面真实可见（见上方渲染图：镇雄街景照片完整出现在画板）。

## 二、A-69 假成功根治（P1，同根第三次复发）

病根（任务单已点）：**诊断只看 `warnings` 空不空，不看丢了多少层**。

### 2.1 修复

1. **层数守恒硬约束**：`input_layer_count == preserved + degraded + ignored`（每被遍历层必落其一），破坏即进 warnings，绝不静默。
2. **绿色「✓ 完整提取」收紧为全满足**（纯函数 `ParseDiagnostics.swift`）：`isValid && warnings.isEmpty && ignored_count == 0 && preserved+degraded >= 可见层数`。`layers.count > 0` 绝不再单独判成功（红线 4）。
3. **有非底板被忽略层时，诊断必显橙色**：「⚠️ 已忽略 N 层（…）。当前列表仅显示 M 个可见层。」—— 与底板层过滤（正常预期）区分：只有「非底板」被忽略（隐藏/空/组/其他）才升级为「注意」，纯文字+底板稿仍判「无风险」（见 §五偏差披露）。
4. 桥接 JSON 透出 `summary`（含 `count_sum_holds` / `ignored_count` / `ignored_summary`），Swift 端才能做完整性判定。

### 2.2 红绿对照（镇雄结构样本，13 层 → 1 层）

| 项 | 旧（R32 遗留逻辑） | 新 |
|---|---|---|
| 诊断色 | 绿色「✓ 矢量文字层完整提取」 | **橙色**：「⚠️ 已忽略 12 层（11 个隐藏 + 1 个底板）。当前列表仅显示 1 个可见层。」 |
| `ignored_count` | 不暴露/不进判定 | 12，明细可读 |
| 守恒 | 不校验 | `13 == 0 + 1 + 12` ✅ |

## 三、A-70 隐藏层不许静默丢弃（P2）

1. 隐藏层分支**必须** `append` 记录，与底板层对称：
   `diagnostics_notes.append(f"跳过隐藏图层: '{name}'（按设计规范不参与转换；勾选「显示隐藏图层」可预览）")`。
2. 汇总：`本文件含 N 个隐藏图层，已按规范跳过`。
3. **「显示隐藏图层」开关**（默认关）：`parse_psd_file(include_hidden=True)` 让隐藏层以 `visible=False` 预览层进入列表（不计入转换 output，不改守恒）。`InspectorView` 复选框勾选 → 重新解析 → 画布/列表显示全部层。

### 偏差披露（必须单列）

1. **主样本 `镇雄.psd` 不在本机**：任务单给的路径 `/mnt/local/128/字幕素材/镇雄.psd` 在本机 `/mnt` 未挂载、全卷搜索无果。按任务单「审核方已定位」但本机环境不同，我**合成等价样本** `docs/r33_evidence/zhenxiong_equivalent.psd`：2848×1600，13 层 = 11 隐藏 pixel + 1 底板 pixel（命名「图层 2」，与任务单实测一致）+ 1 可见 pixel「镇雄夜色」，文字层 0，结构与任务单 §2.1 逐字对齐。复现脚本 `tools/make_r33_samples.py` 已交付，审核方拿原 `镇雄.psd` 跑同 harness 即可直接复验。
2. **`test_psd_import_and_diagnosis.py::test_normal_text_psd_import_and_diagnosis` 的 `assert "无风险"` 断言未改、未弱化**：A-69 初版把 `risk_assessment` 的「注意」升级条件写成 blanket `ignored_count > 0`，会把「纯文字 + 底板」正常稿也误判为「注意」，导致该既有断言失败。我将其收紧为 `non_bg_ignored > 0`（仅「非底板」被忽略才升级），既满足 A-69（隐藏层不再静默/假绿），又保留「纯文字+底板=无风险」这一正确设计预期——**断言原文保持不动**，属逻辑精修而非弱化。
3. **桥接关掉 `extract_thumbnails`**：Swift 端不消费缩略图 base64，旧逻辑对大图白做 44s。关闭后镇雄样本解析 61s→约 17s，且 JSON 不再含巨大 base64（判据不影响，性能修复）。
