## 二、根因（已由审核方在源码层定位，可直接按行号施工）

### A-61 拖放完全缺失 —— 原生壳未注册任何拖放类型

- `FCPXStudioNative/Sources/` 下全部 10 个 Swift 文件（合计 1780 行），检索结果：
  - `registerForDraggedTypes` **0 处**
  - `draggingEntered` / `draggingUpdated` / `performDragOperation` / `prepareForDragOperation` / `draggingExited` **0 处**
  - `NSDragging` 相关 **0 处**
- 主窗口在 `MainWindowController.swift:41-51` 用标准 `NSWindow` 创建，未做任何拖放注册。**`NSWindow` 默认不接收文件拖放**，所以把 PSD 拖到窗口上，系统层面就没有接收方 → 用户感受到的就是"完全没有反应"。
- **重要：Python 侧其实早就实现了，但那是死代码。**
  - `gui/main_window.py:56` → `self.setAcceptDrops(True)`
  - `gui/main_window.py:351-372` → `dragEnterEvent` / `dropEvent`，且已完整支持"单文件 .psd"与"文件夹递归扫描"两种拖入，还会 `_append_psd_files` 追加并自动选中首个新文件。
  - 但交付物 `FCPX Studio Pro.app` 是 Swift 原生壳，`启动FCPX_Studio.command` 直接 `open "$DIR/FCPX Studio Pro.app"`，**PyQt 界面根本不参与运行**。

> ⚠️ **这是本轮最需要记住的一条**：项目存在 PyQt 与 Swift 两套 UI，同一功能可能只在其中一套里存在。**任何 UI 类缺陷，必须先确认交付物走的是哪一套，再改对应那一套**。本轮若只改 `gui/*.py`，用户那边现象不会发生任何变化，等于空转一轮。

## 三、修复要求（给开发 AI）

### A-61 拖放（P1，必须做）

1. 在原生壳实现文件拖放。推荐做法（择一，从简）：
   - 给 `MainWindowController` 的 `window.contentView` 套一层自定义 `NSView` 子类（如 `DropAcceptingView`），在该子类 `init` 中 `registerForDraggedTypes([.fileURL])`，实现 `draggingEntered(_:)`（校验 `.psd` 或目录后返回 `.copy`）、`performDragOperation(_:)`（取 `sender.draggingPasteboard.readObjects(forClasses: [NSURL.self])`）。
   - 或直接在 `InfiniteCanvasView` / 左侧列表容器上注册（用户最可能拖到画布区，**建议画布 + 整个窗口都能接**）。
2. 落盘逻辑必须与现有目录导入**复用同一入口**：`loadPsdDirectory(_:)` 只处理目录，需新增 `importPsdPaths(_ paths: [String])`：
   - 单个 `.psd` 文件 → 追加进 `psdFiles`（**追加，不是清空**），`psdTableView.reloadData()`，并 `selectRowIndexes` + `selectPsdFile(at:)` 自动渲染；
   - 拖入目录 → 沿用现有目录扫描逻辑；
   - 拖入多个混合项 → 逐个分类处理，psd 全部收进来。
3. 去重：同一路径已在 `psdFiles` 中则不重复追加（对齐 PyQt 侧 `_append_psd_files` 的行为）。
4. 拖入非 psd 文件（如 .txt/.jpg）→ **不崩溃、不静默**，给一句明确提示（`NSAlert` 或状态栏文案），例如"仅支持 .psd 文件或包含 .psd 的文件夹"。
5. 拖放视觉反馈：`draggingEntered` 返回 `.copy` 后，窗口最好有可见高亮（边框/遮罩），否则用户仍会怀疑"能不能拖"。此项为加分项，非硬性。

### A-62 单文件打开（P2，必须做）

1. `openPsdDirectory` 改为**文件与目录都可选**：
   - `panel.canChooseFiles = true`、`panel.canChooseDirectories = true`；
   - 加 `panel.allowedContentTypes = [UTType(filenameExtension: "psd")!]`（或 `allowedFileTypes = ["psd"]`），避免用户选到无关文件；
   - `panel.prompt` 改为"打开"。
2. 菜单拆成两条，语义清晰：
   - 「打开 PSD 文件…」→ ⌘O，`canChooseDirectories = false`、可多选；
   - 「打开 PSD 目录…」→ ⇧⌘O，保持原行为。
   - 两条都复用上面新增的 `importPsdPaths(_:)`。
3. **兜底兼容**：⌘O 直接沿用旧行为也可以（允许同时选文件和目录），但不能出现"选了文件却什么都不发生"。

### 红线（违反即不合格）

1. **不许只改 `gui/*.py`**。交付物是 `.app`（Swift 原生），改 PyQt 侧对用户零效果。**要么改 Swift 并重建 `.app`，要么明确说明该功能在 PyQt 侧已存在、本轮不需要改** —— 二选一，不许含糊。
2. 不许触碰 `core/motion_builder.py`（连续三轮红线，sha256 `e859eec3…a255`）。
3. 不许擅自扩大 110 项指纹工具的扫描范围来"适配"本轮改动（会破坏跨轮可比性）。新增/改动的 Swift 文件按 A-60 的独立清单登记。
