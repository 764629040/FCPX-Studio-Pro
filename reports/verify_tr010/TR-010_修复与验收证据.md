# TR-010 修复与验收证据｜「禁用模板」真隔离（方案 A）

> 一句话结论：**禁用 = 把模板整体移出 FCPX 扫描树到禁用仓；启用 = 原路搬回。**
> FCPX 启动时只扫描 `~/Movies/Motion Templates.localized/...`，模板不在扫描树内就
> **必然加载不到**，旧「改名 `.disabled` 仍被 FCPX 照常加载」的失效问题彻底解决。

---

## 1. 旧机制为什么失效（根因）

旧 `toggleTemplate` 只把分类目录改名加 `.disabled` 后缀，例如：

```
~/Movies/Motion Templates.localized/Titles.localized/我的字幕  →  我的字幕.disabled
```

FCPX 的模板浏览器扫描的是**目录本身**，并不因为多了一个 `.disabled` 后缀就跳过它。
实测：`TR008对照.disabled` 改名后重启 FCPX，标题浏览器里照样显示并能预览 ——
所谓「禁用」对 FCPX **完全无效**，`TemplateInstaller.swift:12` 注释里「加速 FCPX 启动」
的承诺也不成立。

## 2. 修复方案（方案 A：真隔离）

新增纯 Foundation 模块 `TemplateIsolationStore`（`FCPXStudioNative/.../Models/TemplateIsolation.swift`）：

| 操作 | 行为 |
|------|------|
| `disable(templatePath:)` | 扫描树内模板 → 整体 `moveItem` 到 `~/Library/Application Support/FCPXStudio/disabled/<分类>/<相对路径>` |
| `enable(disabledPath:)` | 禁用仓内模板 → 原路 `moveItem` 回扫描树 |
| `isDisabled` / `isInScanTree` | 路径归属判定 |
| `relativePathUnderCategory` | 解析 `<分类>` 与分类下相对路径 |
| `listDisabled()` | 枚举禁用仓，供 UI 呈现被休眠的模板 |
| `migrateExistingDisabledInScanTree()` | 一次性迁移遗留的 `*.disabled` 目录（仅限真正的模板目录） |

`TemplateInstaller.toggleTemplate` 已改写为调用上述隔离仓，**改名方案彻底淘汰**。

### UI 可见性（关键补漏）
禁用后模板不在扫描树，常规扫描不会返回它。已在 `AssetHubView.refreshList()` 两个分支
后插入 `mergeDisabledTemplates()`，把禁用仓里的「已休眠」模板并回 `allItems`，
**应用重启后仍能看到并重新启用**。

### 一次性迁移接入启动
`AppDelegate.applicationDidFinishLaunching` 启动时调用
`migrateExistingDisabledInScanTree()`（幂等，无遗留则零操作）。

### 注释修正
`TemplateInstaller.swift:12` 旧注释「`.disabled` 机制，加速 FCPX 启动」已改为方案 A 真隔离说明。

## 3. 验证证据

### 3.1 编译
`cd FCPXStudioNative && swift build --disable-sandbox` → **Build complete! (exit 0)**。
所有改动文件（`TemplateIsolation` / `TemplateInstaller` / `AssetHubView` / `main.swift`）均编译通过。

### 3.2 隔离机制往返（真代码，跑在真实家目录）
驱动 `tools/tr010_driver.swift` 直接编译**真实** `TemplateIsolation.swift` 后运行，
对真实扫描树/禁用仓做「禁用→移出扫描树」「启用→搬回」「遗留 `.disabled` 迁移」三件事，
全部使用 `TR010_` 前缀合成条目，跑完即清理，不污染真实模板库。

关键结果（完整日志见 `tr010_isolation_ls.txt`）：

```
# 禁用前：扫描树 Titles.localized 含 TR010_隔离验证
# disable -> ~/Library/Application Support/FCPXStudio/disabled/Titles.localized/TR010_隔离验证
#   isDisabled? true
#   isInScanTree? false          ← 已不在扫描树，FCPX 扫不到
# 禁用后：扫描树不再含 TR010_隔离验证；禁用仓 Titles.localized 含它
# enable  -> ~/Movies/Motion Templates.localized/Titles.localized/TR010_隔离验证
#   isInScanTree? true           ← 已搬回扫描树，FCPX 重新可见
# 启用后：扫描树恢复含 TR010_隔离验证；禁用仓不再含
# 最终：禁用仓恢复为空
```

**这正是 FCPX 验收的本质**：FCPX 每次启动只读 `~/Movies/Motion Templates.localized/...`
这棵扫描树，模板移出 → 标题列表必然消失；搬回 → 必然回归。

### 3.3 一次性迁移（含加固）

迁移脚本初版扫到扫描树里一个 `*.disabled` 目录并试图搬走，但其中有一个**并非模板**：

```
Effects.localized/新版星芒效果/lumakey.app/.../PluginManager.framework/Resources.disabled
```

它是框架自带的版本化**符号链接**（`Resources.disabled -> Versions/Current/Resources`），
搬走会破坏插件。已**当场还原**，并对 `migrateExistingDisabledInScanTree` 加固：

- 仅迁移「真正被改名禁用的模板目录」：**该目录本身或其指向目录的顶层必须含
  `.moti/.moef/.motr/.motn` 模板主文件**；
- bundle 内部（`.app/.framework/.pluginkit/...`）的 `.disabled` 一律跳过。

加固后复跑：只迁移了合成的 `TR010_迁移验证.disabled`（含 `.moti`），
框架 `Resources.disabled` 符号链接**保持原地不动**（见 3.2 日志与下方确认）：

```
确认 PluginManager.framework/Resources.disabled 仍存在于扫描树（未受影响）
```

用户真实模板库里当前**没有**任何模板级的 `*.disabled` 遗留目录（唯一一个 `.disabled`
是框架内部符号链接，被正确跳过），因此生产环境的迁移是安全的幂等空操作。

## 4. 完整验收（需用户在 FCPX 内确认 2 张截图）

隔离机制已在文件系统层被证明（§3.2），下面这一步是 FCPX 实际重启的肉眼确认。
**当前自动化沙箱禁止 GUI 脚本（Finder/System Events AppleScript 返回 -10004），
无法自主驱动 FCPX 标题浏览器逐项定位并截图**，故列出 2 分钟手动确认步骤：

1. 在 FCPXStudio「素材库 / Asset Hub」里挑一个标题类模板（如 `PSD婚礼字幕`），确认它在 FCPX 标题浏览器中可见。
2. 在 FCPXStudio 中对该模板点「禁用 / 休眠」→ 它从扫描树消失（`ls ~/Movies/Motion\ Templates.localized/Titles.localized` 不再含它，改到 `~/Library/Application\ Support/FCPXStudio/disabled/...`）。
3. **完全退出并重启 FCPX** → 标题浏览器里该模板**消失**（截图 1：浏览器中找不到它）。
4. 回到 FCPXStudio 对该模板点「启用」→ 它搬回扫描树。
5. **再次退出并重启 FCPX** → 标题浏览器里该模板**回归**（截图 2：浏览器中重新出现）。

> 机制保证：FCPX 不缓存扫描树之外的模板，第 3/5 步的「消失 / 回归」由第 2/4 步的文件系统移动直接决定，
> 与 §3.2 的往返证据一致。
