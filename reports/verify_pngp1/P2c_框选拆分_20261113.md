# P2-c 画布框选拆分（2026-11-13）

背景：M.3.20 收口后，拆分只有「按连通块自动拆」一种。用户「体积暂时不管。画布上框个圈再拆的交互要有，可用鼠标拖动框选出来」。本轮按此落地。

---

## 一、口径

拖框圈住某层的一部分，把它拆成独立层：

- 框内**每个够大的连通块各自成层**。
- 同一块被框边切开的，**只取框内那半，框外那半回原层**，所以拆前拆后像素并集不变。
- 框内部分小于 `min_area` 的碎渣不拆、留在原层；框里没东西或只有碎渣 → 如实拒绝，不凭空造层。
- 背景层不参与，PSD 链路不开放。

`min_area` 沿用 M.3.20 的自适应公式：`max(12, min(int(0.0008*W*H), 层像素 // 8))`。

---

## 二、core

| 位置 | 改动 |
|---|---|
| `_layer_full_rgba(path, bbox, canvas)` | 新增。层图按 bbox 贴回整幅画布，返回整幅 RGBA + alpha 数组 |
| `_write_mask_png(full, mask_group, out_dir, name)` | 新增。把指定像素单独存一张 png，返回 path/bbox/像素数 |
| `split_layer_png` | 改为复用上面两个工具，行为不变（12 张回归逐条一致已验证） |
| `split_layer_png_region(path, bbox, canvas, out_dir, region)` | 新增。返回 `(blocks, rest)`：整层 8 连通 label，只取「框内有像素且框内部分 ≥ min_area」的 label，按框裁出 |
| `split_layer_model(parsed, split_dir, index, region=None)` | 加 `region` 参数。None 走原全层拆；有 region 时原层改名不变但换成 `rest`（notes 追加「框选拆出 N 块，框外留在这层」），拆出块插在其后，命名 `<原名>_框拆N`；整层被框走则原层移除 |

## 三、GUI

**`InfiniteCanvasView`**
- 信号 `region_picked_signal(object)` / `region_cancelled_signal()`；状态 `_region_pick` / `_region_origin` / `_region_box`。
- `begin_region_pick()` 进模式（十字光标），`cancel_region_pick()` 退出并清临时矩形，`keyPressEvent` 拦 Esc。
- 左键只画虚线框（cosmetic 虚线 + 半透明蓝填充 + 顶层 z），右键即取消，**中键仍可平移视野**（大图上需要挪动时不会被框选吞掉）。
- 框太小（`REGION_MIN_SIDE = 4.0` scene 单位）按误触放弃，静默退出。
- `drawForeground` 画顶部橙色提示条「拖框选要拆出的部分 · Esc 取消」。

**`CanvasContainer`**：`region_picked_signal(int, object)` 转发时附上图层 index，只在右侧（转换结果）画板生效。

**`inspector_panel`**：`layer_region_split_requested` 信号；单选右键菜单在「按连通块拆分这层」之后加「框选拆分这层（在右侧画板拖框）」。

**`main_window`**
- `_on_begin_region_split(index)`：先过 `_layer_edit_ready()` 与背景层检查，再进模式。
- `_on_region_picked(index, rect)`：调 `split_layer_model(..., region=rect)` 后走既有 `_apply_layer_edit`。
- `_on_region_cancelled()`：静默退出，不打扰。

## 四、过程中修掉的两个真 bug

### 1. 右栏整层错位（既有问题，不是本轮引入）

`ConvertedLayerGraphicItem.update_geometry_from_info` 对贴图图层用 **pixmap 整幅尺寸**定 rect，却按 **bbox 中心** `setPos`。边缘导出的层 PNG 都是整幅画布尺寸、本身已带画布坐标，再按 bbox 中心摆就等于把整幅图平移了 (bbox 中心 − 画布中心)。

后果：A 夹具的 `SALE` 大字、星星、黄线长期被平移出画板外（早前截图里右栏只看到「2026 AUTUMN」和红球，就是这个原因）。单层偏移在 32% 缩放下不明显，**这轮框选把球拆成半块、两块被拉开 242px，才把它暴露出来**。

修法：整幅尺寸的层 PNG 直接把 pos 归零（`setPos(0,0)`），并给该图元传入画板尺寸做判断。修后 A 夹具右栏完整显示标题、副标题、星星、黄线，与左栏原稿一致。

### 2. 坐标 y 轴符号写反

初版 `_scene_rect_to_image` 按「scene y 与图像 y 反向」写（`img_y = H/2 - sy`），截图显示框只套住球上半截。

真实关系是**同向**：图元 `setPos(motion_x, -motion_y)`，而 `motion_y` 是「层中心相对画布中心的偏移、向下为正」，所以 `img_x = sx + W/2`、`img_y = sy + H/2`。改为同向后框正好套住球右半全高。

**教训**：发送端和接收端用同一个错公式，测试会假通过（拆出来了、像素差也 0，但框的位置是错的）。这类几何改动必须靠**截图肉眼核对框与目标是否重合**，不能只看数据断言。

## 六、仍待质控拍板

1. 拆分后层数会超过源文档层数，层标签出现「参与转换 9 / 文档总计 8」。语义没改（文档总计指源文档原始层数），但看起来像对不上，是否调整显示口径未定。
2. 拆出层的 `pixels` 按实际 `alpha>8` 计数，与 P1 旧层记录口径不同。只影响展示与合并时的主类判定，不影响像素。
3. 合并/拆分编辑不写回分层清单（只在本次导出生效），这个取舍仍未经用户确认。
4. 图元有 1px 白色描边，拆开后两块交界会出现一条细线。数据无缺失（100% 缩放核对过），是否要去掉边描未定。
