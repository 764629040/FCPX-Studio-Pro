## 硬约束（用户明确否决）

**禁止任何自动退出/重启 FCPX 的功能。** 本轮零实现：

- 全量 Swift 源码精确词表扫描 `NSRunningApplication / relaunch / killall / osascript / quitApp / restartApp / terminateApp( / NSWorkspace.shared.launchApplication` → **0 命中**。
- `Process.terminate()` 命中 7 处，逐个核实全是 Python 子进程超时回收（`process.terminate()` / `proc.terminate()`，后接 `kill(pid, SIGKILL)`），与 FCPX 无关。
- `NSApp.terminate(nil)` 仅位于 `MainWindowController.windowWillClose`，是用户主动关闭**本 App** 窗口时退出本 App，既非 FCPX 也非自动行为。
- 文案里「重启 FCPX 后可见」只做**告知**，何时重启完全由用户决定，代码不触发任何重启。
- 现场：验证时 `Final Cut Pro` 与 `FCPX Studio Pro R2.app` 均在运行。本轮**不启动/重启 App、不重启或退出 FCPX、不触碰用户真实模板库**。

## 改动清单（只做两件事）

### 1. 成功提示文案

`Views/AssetHubView.swift` 新增文案唯一真源：

| 常量/函数 | 值 |
|---|---|
| `effectNotice` | `已生效，重启 FCPX 后可见` |
| `toggleSuccessMessage(name:enabled:)` | `模板「X」禁用完成：已生效，重启 FCPX 后可见` / `模板「X」启用完成：已生效，重启 FCPX 后可见` |

- 文案由 public 常量/函数统一提供，生产弹窗、批量确认、离屏渲染物证、harness 断言全部引用同一真源，杜绝「代码改了截图还是旧文案」。

### 2. 禁用前二次确认

**确认弹窗文案（逐字）**：

> 该模板若正被某个工程使用，重启 FCPX 后该工程中的对应片段可能显示缺失；模板文件本身不删除，随时可在本 App 启用回来。
>
> 模板：\<模板名\>

按钮：`确认禁用` / `取消`。仅**禁用**方向弹；启用方向不弹。取消直接 `return`，在任何文件操作之前，模板原地不动。

覆盖的 UI 路径（避免绕过或弹 N 次）：

| 路径 | 处理 |
|---|---|
| 卡片胶囊 Toggle → `onToggle` → `toggleTemplateItem` | 单项二次确认 |
| 列表视图「状态」按钮 `onToggleStatusClicked` | 走 `toggleTemplateItem`，同上 |
| 「全选/全停」`onSelectAllClicked`（批量禁用） | 入口做**一次**总确认，逐项 `skipConfirmation: true`，避免 N 个弹窗；取消则整套不动 |
| `ResourceCardView` 无 `onToggle` 的降级兜底分支 | 补同款二次确认，封住旁路 |
| `toggleItem(at:)` | 无 UI 的编程接口（harness/表格契约），**不弹确认**，已加注释；生产 UI 无调用点 |

`alertResponseHandler` 是测试注入点（生产恒为 nil），让 harness 能精确模拟「取消 / 确认」并抓取真实弹窗文案，不阻塞、不抢焦点。
