## 3. 实现要点

- `onSingleQuarantineClicked(_:)` 内先构造 `NSAlert`（`.warning`），走 `presentConfirmation(alert)`；`!= .alertSecondButtonReturn` 直接 `return`，**在任何文件操作之前**。
- 确认后**原样保留**原有逻辑：`quarantine(issue:)` → 状态栏 → `AssetCacheManager.shared.invalidateAll()` → `startScan()`，一字未改。
- `presentConfirmation(_:)` 只负责「返回用户决策」：生产 `alertResponseHandler == nil` 时直接 `alert.runModal()`，**生产确认不弱化、不绕过**；不构造弹窗、不含任何单条隔离文案。
- `alertResponseHandler` / `startScanOverride` 是 TR-013 风格仅测试注入点，生产恒 `nil`。`startScanOverride` 让 harness 计数 `startScan` 并**阻止真实全盘扫描**，从而保证全程不读写 `~/Movies/Motion Templates.localized`。
- 批量 `onQuarantineAllClicked`：FCPX-055 的 NSAlert 对象、`messageText`、`informativeText`、两个按钮、`.alertFirstButtonReturn` 判定、`quarantineAll(issues:)`、`invalidateAll()`、`startScan()` **全部逐字未动**；只把 `alert.runModal()` 换成等价的 `presentConfirmation(alert)`，使 harness 能注入「取消」并捕获该弹窗以证明无重复弹框。生产 `alertResponseHandler == nil` 时两者行为完全一致。**批量 handler 内没有任何单条确认调用、没有循环调单条 handler。**
- `issues` 是 `public private(set)`，harness 走项目既有注入口 `applyReport(_:)` 预置合成 `DoctorReport`，**未改访问级别**。
- 单条 handler 是 `@objc private`，harness 用 `view.perform(NSSelectorFromString("onSingleQuarantineClicked:"), with: button)` 触发，编译运行均正常。
