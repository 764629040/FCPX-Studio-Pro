一、真机点验的四项不合格 → 处置
--------------------------------------------------------------------------
1) 右侧「幅面规格」被一大坨红色 XML 术语诊断挤掉
   - 根因：ParseDiagnosticsState.resolve 把 PSD 解析告警（含 bridge summary 等技术词）整串灌进 diagnosticsBox。
   - 处置：InspectorView 新增 updateMotiReadOnlyInfo(...)，只读态绕开 PSD 诊断路径；
           resolutionLabel 加固定最小高度 + required 垂直抗压，常驻显示「📐 幅面规格 1920×1080」；
           诊断收敛为小徽标「ⓘ … 详情 (N)」，默认折叠，展开后是纯白话，无 XML 节点名 / 参数 id / 英文字段。
2) 画布全黑
   - 根因：.moti 分组层没有位图贴图、文本为空，drawLayer 什么都不画。
   - 处置：InfiniteCanvasView.motiPreviewMode + drawMotiPlaceholders(...)：
           彩色圆角框 + 序号徽标 + 文字内容（无文字则层名占位）+ 顶部「只读预览 · 共 N 层」。
           此路径不依赖 backgroundPreview / fallbackPngPath / PSD 位图。
3) 只读态还显示「图层已锁定（⌘L 解锁）」
   - 处置：只读态隐藏 lockBannerBox；lock 按钮 toolTip 改「只读，不可编辑」；
           performKeyEquivalent 吞掉 ⌘L；新增常驻标签「🔒 只读，不可编辑」。
           注意：二进制里仍保留 1 处「⌘L 解锁」字节，属于非只读态分支，运行时由 harness 断言只读态不显示。
4) 婚礼模板 11 个 <layer> 只显示 1~2 层
   - 根因：旧 parser 用 scene.elements(forName: "layer")，只拿 <scene> 的直接子节点。
   - 处置：MotiDocumentParser 改自 <scene> 起递归深度优先 collectLayers(from:depth:into:)，
           保留文档顺序；新增 depth / nestedLayerCount / containerLayerCount。
   - 全库实测：1226 个 .moti 中，764 个文件的 layer 节点 XML 父节点不是 <scene>（XML 树口径，
     早先按缩进估的 594 已作废）。极端样本「-PVFX便签字幕/10 字母/10 字母.moti」564 层，
     旧版只拿到 5 层，现解析 564 层。
