## 1. 扫描口径与一个必须写下来的坑

口径逐行对齐源码：

| 环节 | 源码 | 扫描器 |
|---|---|---|
| 收层 | `collectLayers`（`MotiDocumentParser.swift:252`）：scene 起深度优先、前序、任意深度 | `collect_layers()` |
| 层内 style | `allStyleElements(in:)`（`:385-396`）：只走 layer 子树 | `descendants_named(el,"style")` |
| 取文本 | `parseLayer`（`:326-335`）：`对象(2) → 文本(369) → <text>` | `layer_text()` |
| 取填充色 | `resolveTextColor`（`:486-528`） | `resolve_color()` |
| 通道取值 | `explicitValue`（`:411-424`）+ `declaredValue`（`:429-435`）+ `rgbHex`（`:440-457`） | `declared_value()` / `rgb_hex()` |
| 面板空值 | `InspectorView.swift:1118 / 1142` + `applyTextStyleEnabledState`（`:1153-1187`） | 源码直读 |

**坑（第一版结论错到反向，必须记）**：Motion 的数值**不一定写在 `parameter` 的 `value` 属性上**，
大量文件写在子节点 `<curve type="1" default="1" value="1">` 里。只读 `value` 属性的扫描器会得到：

```
错误口径：173 个文件 / 657 个文字层「取不到色」
正确口径：111 个文件 / 141 个文字层「取不到色」   ← 差 516 层，4.7 倍
```

差的 516 层全是 `表面/渐变` 里带 `<curve value>` 的正常颜色（含 `婚礼模板.moti`、`PSD婚礼字幕` 全系）。
**若核对按 657 报，结论会从「少量真缺口」变成「解析器大面积失效」，方向性错误。**

## 4. 真缺口：`面/渐变` 39 层（全表见 `缺口清单_39层.tsv`）

`resolveTextColor` 的三条渐变兜底（`:505-527`）：

```swift
(childParameter(style, ["表面"]), ["渐变"],  ["颜色"])   // 表面/渐变
(childParameter(style, ["Face"]), ["Gradient"],["Color"]) // Face/Gradient
(style,                            ["渐变","Gradient"], ["颜色","Color"]) // 直挂
```

`面/渐变`（`面` id=14 下的 `渐变` id=17）**三条都不覆盖**，于是取色返回 `nil`。而这条链里确实有值：

```
名称条 01（名称条 1/名称条 01，L3 id=1825779821，text="총 3문제 성공!"）
  面(14) > 渐变(17) > RGB(1) > RGB1 > 颜色(3) > 红/绿/蓝 → #FFE700（红 1.0 / 绿 0.906 / 蓝 0）
  产品解析器实测：color=(nil)   ← 「未取到」
```

38 个文件里 5 组是重复模板（`超人/…` 与主目录同名文件 sha 相同），按内容去重 **33 个**。
缺口全部集中在 `Titles.localized/03综艺动漫/` 与 `PSD婚礼字幕` 之外的综艺字幕包（明细见 TSV）。

> 注意：这条不是「补一条路径就好」这么简单——`表面` 的取色优先级排第三，`面` 是它的另一种写法；
> 补 `面/渐变` 会不会与「轮廓/颜色 不作主色」的既定口径冲突，需要问题单定，本报告只给事实。

## 9. 对《已知局限_颜色边界模板_20261112.md》一稿的复核

仓库里已有一份未跟踪的一稿（7 处 / 6 个唯一文件，判定「不修」）。**结构口径我独立复现，一致；
但「面板禁用」这个结论只有 3 个路径成立，其余 4 条被实测推翻，且这 3 条的根因都不是「层外 style」。**

| # | 模板 | 一稿结论 | 真解析器实测 | 差异 |
|---|---|---|---|---|
| 1 | `情感 02` | 禁用·未取到（称用户真机所见） | layers=3，**三层文本全空** | 该文件没有文字层，面板无「文字样式」可禁用；「真机所见」对不上，需核对是哪一层 |
| 2 | `扩音器01` | 禁用·未取到 | L3「어어어어어!!」nil ✔ | 未取到成立，但根因是**层内 `面/渐变` 不被支持**，不是层外 style |
| 3 | `超人/扩音器01` | 禁用·未取到 | 与 #2 sha 相同 | 同上（同一份文件的副本） |
| 4 | `全知/点文本 02` | 同构推断·禁用 | L3「지」nil ✔ / L4「무」#FD5F54 | 未取到成立，但 L3 的 `面` 只有 `纹理/源媒体`（**图片填充，本来没有纯色**），不是 style 位置问题 |
| 5 | `子条 03` | 同构推断·禁用 | **L1 #FEFCFB（面/颜色）** | **不成立**——层内取到了，面板有值 |
| 6 | `美味家伙 05` | 同构推断·禁用 | **L4 #FF3299（面/颜色）** | **不成立**——同上 |
| 7 | `红色简单` | 同构推断·禁用 | **layers=0** | **不成立**——该文件读不出任何图层，没有控件可禁用 |

结论修正：

- 「层外 `<style>` 有 7 个文件 / 6 个唯一」→ **成立**（本报告 §6 独立复现同一批文件）。
- 「这 7 处面板都禁用」→ **不成立**：真值是 **3 个路径 / 2 个模板**（#2 #3 #4），
  且 #2#3 的根因是 `面/渐变`，#4 的根因是图片填充，**没有一处是由「层外 style」直接造成的**。
  原因很直白：层外 `<style>` 挂在 `group > scenenode` 上，那些对象**根本不是 layer**，
  压根不会出现在图层表里，也就没有控件可以被它禁用。
- 一稿把 #5#6#7 标成「同构推断·禁用」而没开 App 点检，这三条正好是错的；
  建议按本报告 §4 的 `面/渐变` 39 层重写根因，别把「结构同构」当「面板症状」。
