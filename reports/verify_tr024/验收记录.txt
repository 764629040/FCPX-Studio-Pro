三、滤镜链（四种模式，证明没有像素循环）
───────────────────────────────────────────────────────────────────────────
公共前处理：CIImage(cgImage:) → 目标色 NSColor 统一转 sRGB 分量。

  direct    直接替换
            CIImage(color: 目标色, alpha=1).cropped(原图 extent)
            → CIBlendWithAlphaMask(inputImage=常量色, backgroundImage=全透明, maskImage=原图)
            out.rgb = 目标色 ; out.a = 原图 alpha
            为什么不用 CIColorMonochrome(intensity 1.0)：它的语义是 out = color × luma，
            纯黑墨 luma=0 → 换完还是黑的。实测反例（同一张黑字源图、同一个目标色）：
              CIColorMonochrome(1.0) 不透明像素均值 R=0.0 G=0.0 B=0.0   ← 完全无效
              direct（本条链）       不透明像素均值 R=41.0 G=209.0 B=255.0 = #29D1FF

  luminance 明暗上色（默认）
            CIColorControls(saturation=0)                     ← 取亮度
            → CIColorMatrix(out = target − (target − dark) · luma, dark = target × 0.35,
                            aVector=(0,0,0,1), bias 的 alpha 分量 0)  ← alpha 原样穿透
            暗墨（luma≈0）落到目标色亮部 → 黑字换色后就是目标色本身；原图越亮越暗。

  invert    反相
            CIColorInvert                                       ← 明暗映射整体掉头
            → CIColorControls(saturation=0)
            → CIColorMatrix(同 luminance 的公式)
            墨芯落到目标色的暗端（#29D1FF → 14,73,89），和 direct 一眼能分开。

  hueRotate 色相旋转
            CIImage(color: 目标色) + CIBlendWithAlphaMask（同 direct）
            → CIHueAdjust(angle = +30°)
            无彩源图上 CIHueAdjust 单独用是恒等变换（黑字换了等于没换），
            所以先按目标色建立色相基准再转 30°，屏幕上才有可比的差异。

  多色判断（提示行 + auto 分流，全部 Core Image 面积滤镜，1×1 结果）：
            CIAreaAverage × 10（3×3 宫格 + 全图）、CIAreaMaximum、CIAreaMinimum
            → 每条结果渲染成 1×1 RGBA8（4 字节）后读饱和度/色相，
              色相跨度 ≥ 25° 且饱和 ≥ 0.15 判「含多色」；全图最大饱和 < 0.10 判「无彩」。
            auto：无彩 → direct；有彩 → luminance。

  零像素循环自证：
            PngRecolor.swift 里只有三处循环：3×3 宫格（9 次）、极值滤镜名（2 次）、
            宫格染色相两两比较（样本 ≤ 12 个）。没有 stride / withUnsafeBytes / 逐像素访问，
            唯一的像素级读取是上面那几个 1×1 的 4 字节结果。

四、验收 #2：导出图与屏幕同色

导出路径：真调 MotionBuilderSocket.shared.buildTemplateResult(psdPath:outputDir:templateName:layers:)

          产物：/tmp/tr024_export/<模式>/Media/0_black_text_tr024.png（1200×600 RGBA）
          四种模式各导出一次，全部 success=true。

屏幕侧取值方法（脚本 tools/tr024/compare_means.py，可复现）：
  1. 截图里自动定位画板：截图经显示器色彩配置转换，画芯 #121418 落盘是 (23,26,32)，
     所以不写死颜色，而是取出现频次最高的 8 种颜色里「在自身 bbox 内填充率最高」的那块矩形；
  2. 画板内取得墨色：出现次数最多的非背景色 = 墨色本体（这样 12% 白虚线安全框、
     蓝色十字准星这些「比暗墨还远离背景」的图元不会被误当墨色）；
  3. 取墨色 ±6 的邻域求均值 —— 邻域即无抗锯齿的厚笔画像素，边缘不被拖进均值。
导出侧同口径：alpha≥250 的像素 → 墨色众数 → 众数 ±6 邻域求均值。

  模式        屏幕均值 R,G,B            导出均值 R,G,B            逐通道差值(屏−导)
  直接替换    (  41.0,  209.0,  255.0)  (  41.0,  209.0,  255.0)  (-0.0, -0.0, -0.0)
  明暗上色    (  41.0,  209.0,  255.0)  (  41.0,  209.0,  255.0)  (-0.0, -0.0, -0.0)
  反相        (  14.0,   73.0,   88.9)  (  14.0,   73.0,   89.0)  (+0.0, -0.1, -0.1)
  色相旋转    (  98.0,  186.0,  255.0)  (  98.0,  186.0,  255.0)  (-0.0, -0.0, -0.0)

  墨色众数（排除抗锯齿）：屏幕与导出四种模式全部逐值相同
    直接替换 (41,209,255) / 明暗上色 (41,209,255) / 反相 (14,73,89) / 色相旋转 (98,186,255)

  形状（alpha）保持：源 PNG alpha 与导出 PNG alpha 差异像素

六、界面落地（要求 #4 逐条对账）
───────────────────────────────────────────────────────────────────────────
· 分组「位图换色」照「文字样式」的写法复制：同一套 mainStack 垂直分组 + TypeScale.bodyBold 标题 +
  36pt 标签 + NSColorWell/HEX 输入，没有另起设计系统。
· 仅当 layer.isBitmapLayer 可见；文字层整组隐藏。同时把「文字样式」在像素层上隐藏：
  像素层的字号/对齐/颜色本来就是空的（全「未取到」），两组互斥、互不占位，
  否则同一栏里两组一起挤，行会叠在一起（这是本轮踩到并修掉的布局问题）。
· 色块 NSColorWell（自带系统取色器/吸管）+ HEX 输入；NSColorPanel.shared.showsAlpha = false，
  只改 RGB 不改 alpha。取色 → 转 sRGB → 存 HEX → 立刻 onLayerModified → canvasView.needsDisplay。
· 模式下拉：自动 / 直接替换 / 明暗上色 / 反相 / 色相旋转（tag = RecolorMode.rawValue）。
· 多色提示：CIAreaAverage 面积采样判定，命中即在控件下方显示橙色「原图含多色，换色后变单色」
  （真机证据 tr024_5_多色原图提示.png）；auto 模式还会显示「自动：原图无彩 → 直接替换 / 有彩 → 明暗上色」。
· 空态：无贴图 → HEX 显示「无贴图」+ 控件禁用 + toolTip「该图层没有可用的贴图文件，换色不可用」；
  未设色 → HEX 显示「未设置」，色块用灰底占位（不拿默认色冒充已换色）。
· 只读 / 锁定：复用同一处判据 editable = !motiReadOnlyMode && !layer.isLocked，只读态标题变「位图换色（只读）」。
