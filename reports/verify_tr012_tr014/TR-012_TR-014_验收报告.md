## 2. TR-012

### 2.1 根因（改代码前实测坐实，非推测）

基线探针 `baseline_layout_and_rootcause.txt`：**13 PASS / 0 FAIL**。逐项事实：

1. `updateTierStats()`（HEAD `:3361`）计数**基于 `allItems`**，不是 `plugins` / `groupItems` / 磁盘扫描结果：
   `:3362 let total = allItems.count`、`:3363 let enabledCount = allItems.filter { $0.isEnabled }.count`。
2. 同一个 `tierStatsLabel` 有 **3 个写入口**，两套互相冲突的口径：

   | 位置 | 数据源 | 文案 |
   |---|---|---|
   | `:1417` | 无 | `当前组共 0 套模板` |
   | `:1442`（`loadTemplatesForSelectedGroup()`） | `plugins` ← `groupItems[selectedGroupIndex].items` **值拷贝快照** | `当前组共 N 套模板（已启用 X / 已休眠 Y）` |
   | `:3386`（`updateTierStats()`） | `allItems` 全量 | `当前分类（…）：共 N 套（已启用 X / 已休眠 Y）｜内置…` |

3. `toggleTemplateItem` 成功分支（`:1795–1817`）只同步了 `allItems[idx]`、`plugins[idx]`、`card.item`，**完全没有同步 `groupItems`**。静态证据见基线输出 C 段。
4. 因此 TR-013 加的 `updateStatusLine(overrideMessage:)` 确实能**即时**算出 279/1，但 `groupItems` 仍是旧快照。用户再点一下分组（`:3840`）、搜索（`:1204`）、tier 筛选或刷新列表，`loadTemplatesForSelectedGroup()` 就从旧快照派生 `plugins` 并用 `:1442` 直接写统计条，把数字**打回 280/0**，连带 `plugins` 的启用状态也一起回退。

基线复现链（280 套纯内存模板，零磁盘操作）：

```
[B0] loadTemplatesForSelectedGroup()            -> 当前组共 280 套模板（已启用 280 / 已休眠 0）
[模拟禁用 1 套，仅同步 allItems/plugins，groupItems 保持旧快照]
[B1] applyFilterAndSort()/updateTierStats()     -> 当前分类（字幕）：共 280 套（已启用 279 / 已休眠 1）...
[B2] 之后任意一次 loadTemplatesForSelectedGroup() -> 当前组共 280 套模板（已启用 280 / 已休眠 0）  ← 被打回
     同时 plugins 里 isEnabled=true 的数量 = 280  ← 也被旧快照重置
```

**结论**：不是「少加了一次调用」，而是**双写入口 + 口径冲突 + `groupItems` 快照未同步**。TR-013 的补调用只解决了即时一帧，没解决状态回写链路。

### 2.2 修法

1. **单一真源**：`updateTierStats()` → `public func refreshTierStats()`，口径恒为 `allItems`；`tierStatsLabel?.stringValue` 现在**全文件只剩 1 处**（`refreshTierStats()` 内），`:1417` / `:1442` 改为调用它，彻底删掉第二个写入口。静态断言见 harness 第 2 节。
2. **同步全部内存模型**：toggle 成功分支用 `TemplateItem.buildItemIndex(from: allItems)` 建 O(1) 索引，一次性同步 `plugins` / `groupItems` / `cardViews`（对路径已从扫描树变为禁用仓的项用 `oldPath` 兜底匹配）。这是根因的核心修复。
3. **显式回写**：成功分支在 `updateStatusLine(overrideMessage:)` 之外显式调用 `refreshTierStats()`，不再依赖间接调用。
4. **可测性注入**：`public var toggleExecutor: ((TemplateItem) throws -> TemplateItem)?`，生产恒为 `nil` 走 `TemplateInstaller.shared.toggleTemplate`，harness 注入纯内存实现，使端到端 toggle 验证**完全不碰真实模板库**。
5. **封旁路**：`ResourceCardView` 无 `onToggle` 的降级路径成功后触发 `onToggleCompleted`，由 `AssetHubView` 注入 `refreshList()` + `refreshTierStats()`。
